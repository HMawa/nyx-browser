# 审查单：整页长截图（M3）

> 交付口径：现象 → 取证（文件与行号）→ 改了什么 → 验证数字（含端到端实测）→ 能证明什么 / 不能证明什么 → 复验命令。
> 日期：2026-11-23｜提交：`feat(page): 整页长截图（CDP captureBeyondViewport，超高截断可见）`

---

## 1. 现象

用户那句「抓取要做到，页面上所有的图面或标志全能保存到本地」之外，还有一句更早就有的抱怨：**「页面截图只截到一屏」**。

原来的入口是「更多 → 页面截图」，实现是 `wc.capturePage()` 后直接写 PNG（`src/main.js` 的 `nyx:page:screenshot`），它只截**可视区**。一篇长文要留档，得手动滚屏截七八张，然后自己在看图软件里对缝——这也是为什么很多「网页存档」工具都带整页截图。

---

## 2. 取证

| 位置 | 事实 |
| --- | --- |
| `src/main.js` 的 `nyx:page:screenshot` | `showSaveDialogSync` → `await wc.capturePage()` → `fs.writeFileSync(picked, image.toPNG())`；**`capturePage()` 不带参数=只截视口** |
| `src/renderer/index.html:56-59` | 「更多」菜单只有 `#more-screenshot`（页面截图），没有整页入口 |
| `src/core/toolbox.js` | 工具箱已经在用 `webContents.debugger`（CDP）抓包，说明这条通道在本项目里是可用且被依赖的 |
| Chromium 156（Electron 45.3.2） | `Page.captureScreenshot` 支持 `captureBeyondViewport: true`，一次就能拿到滚动区域 |

结论：不必自己滚动拼图（拼图会让固定定位的导航栏重复出现、把懒加载内容截成半张），**用 CDP 一次截整页**更稳。

---

## 3. 改了什么

### 3.1 新增 `src/core/fullshot.js`（纯逻辑）

| 函数 | 做什么 |
| --- | --- |
| `buildMetricsScript()` | 注入页面量尺寸：`documentElement` / `body` / `window` 三者取最大的 `scrollWidth`、`scrollHeight`，另带 `devicePixelRatio`、`readyState`、`hasContent` |
| `planFullshot(metrics)` | 判断能不能截、截多大：量不出 → 拒绝并给中文原因；超过 `MAX_HEIGHT = 20000` 或 `MAX_WIDTH = 4000` → 截到上限并写「只截到」；长宽都合规但总量超过 `MAX_PIXELS = 4000 万` → 按 `sqrt(MAX_PIXELS/(w*h))` 等比缩并写「按比例缩到」 |
| `describeFullshot(plan)` | 状态提示一句话（普通 / 有截断 / 失败三种说法） |
| `fullshotFilename(now)` | `整页-2026-11-23-10-05-07.png`，同一页连截两次不撞名 |
| `humanPixels(n)` | 像素数说成「2.0 万」量级 |

`MAX_PIXELS` 单列一条的理由写进了注释：4000×20000 = 8000 万像素，PNG 编码前的位图就 320 MB，够把进程顶爆；4000 万（约 160 MB）是「能截下来也不至于卡死」的折中。

> 这里踩过一个设计矛盾：最初 `MAX_PIXELS` 取 8000 万，正好等于 `MAX_HEIGHT * MAX_WIDTH`，于是「长宽各自合规但总量超限」这条分支**永远走不到**——断言直接把它抓出来了。改成 4000 万之后分支可达。

### 3.2 `src/main.js`：新增 `nyx:page:fullshot`

流程：取活动标签 → `executeJavaScript(buildMetricsScript())` → `planFullshot` → **先 `showSaveDialogSync`**（取消就一张不生成）→ 需要时 `wc.debugger.attach('1.3')` → `Page.enable`（最多等 2 秒，不回执也继续）→ `Page.captureScreenshot { format:'png', captureBeyondViewport:true, clip:{x:0,y:0,width,height,scale:1} }` → 写盘 → 返回 `{ok, path, bytes, width, height, capped, note, summary}`。

三条硬约定：

- **先弹框再截**：用户取消时连 CDP 都不碰；
- **只摘自己挂的调试通道**：`attachedHere` 只在 `!wc.debugger.isAttached()` 时为真，`finally` 里也只摘自己挂的那条——工具箱抓包或 DevTools 挂着的通道绝不动；
- 成功与两类失败都落诊断（`PAGE_FULLSHOT` / `PAGE_FULLSHOT_METRICS_FAILED` / `PAGE_FULLSHOT_FAILED`）。

另加一个**验证旋钮** `NYX_FULLSHOT_PATH`：自动验收点不了模态保存框，允许用环境变量指定落点（与 `NYX_TAB_SLEEP_MS` 同一性质，界面永远走保存框）。

### 3.3 界面

- `src/renderer/index.html`：`#more-screenshot` 之后新增 `#more-fullshot`（▤「整页长截图」，副标题写明「连滚动区域一起截，超高会截断并告诉你」）。
- `src/preload.js`：`pageFullshot: () => ipcRenderer.invoke('nyx:page:fullshot')`。
- `src/renderer/renderer.js`：`takeFullshot()` —— 有截断时标题叫「整页长图已保存（有截断）」、level 用 `info`（不是 `ok`），消息里带 `summary`、路径与 KB；取消单独一句；失败给中文原因。

## 4. 验证

| 项目 | 结果 |
| --- | --- |
| `node scripts/verify-fullshot.js` | **11 / 11 通过**（纯 Node，不启动 Electron） |
| 端到端 `node temp\probe-fullshot.js` | **成功**：隔离 userData 起实例 → 打开高 3600 像素的本地页 → `window.nyx.pageFullshot()` → `{"ok":true,"width":1266,"height":3600,"capped":false,"bytes":62002}`；自解析 PNG 的 IHDR 得 **1899×5400**（CSS 1266×3600 × dpr 1.5），**不是一屏** |
| 全量 `npm run verify` | **55 个脚本 / 55 通过 / 0 失败 / 0 跳过 / 1255 项** |

11 项断言覆盖：正常尺寸不截断；超高截断并写「只截到」与原高；超宽截断；长宽合规但总量超限按比例缩且不放大；量不出尺寸四种输入全部拒绝；提示三种说法；文件名带时间戳且不撞名；`humanPixels`；量尺寸脚本只读（不写 DOM、不发请求、不碰存储）；主进程契约（先弹框、`captureBeyondViewport`、按量好的尺寸下 clip、只摘自己挂的通道、诊断落痕、返回带 `capped`）；界面三处接线。

**探针踩的两个坑（值得记）**：

1. 忘了给 Electron 传 `--remote-debugging-port`，表现是「主窗口没起来（CDP 连不上）」；
2. CDP 消息在 Node 的 `WebSocket` 里是 **MessageEvent**，我直接 `JSON.parse(String(event))` 得到 `"[object MessageEvent]"`，解析静默失败 → 每次调用都 90 秒超时。改成 `event.data` 之后一次通过。

另外 `window.nyx.createTab(url)` 返回的 Promise **要等新页加载完才 resolve**，探针里不能 `await` 它（否则整段卡住）——与既有界面回归脚本的写法一致：发出去就不等。

## 5. 能证明什么 / 不能证明什么

**能证明**：点「整页长截图」能拿到**覆盖滚动区域**的一整张 PNG；页面过高/过宽会截断，并把「截到多少、为什么」写在提示里；量不出尺寸时拒绝而不是截白图；取消保存框不会产生文件；不会打断工具箱抓包或 DevTools 的调试通道。

**不能证明**（如实写）：

1. **固定定位元素只出现一次**——CDP 一次性渲染整页时，`position: fixed` 的导航栏通常只画在顶部一份；这是"整页"的固有取舍，不是缺陷，但和"滚动拼图"的观感不同；
2. **动画/懒加载**：截图瞬间页面若正在播动画或还在懒加载，截到的是那一帧；
3. **父元素被 `overflow: hidden` 裁掉的内容截不到**（`scrollHeight` 本身不含它们）；
4. **隐私模式允许截图**：这是本地渲染结果，不外发、不落代理，但**落盘位置是用户自己选的目录**——这一点在对话里要讲清楚，别让人误以为隐私模式下什么都不落盘；
5. 端到端只验了 `file://` 页面，**没有在真实复杂站点（超长文章、无限滚动）上人眼比对**。

## 6. 复验命令

```powershell
cd D:\Nyx-src
node scripts\verify-fullshot.js      # 期望 11 / 11
node temp\probe-fullshot.js          # 期望「✔ 是整页长图（不止一屏）」，PNG 高 ≈ 页面高 × dpr
node scripts\verify-all.js           # 期望 55 个脚本 / 1255 项全绿
```

手工：打开一篇长文 → 更多 → 整页长截图 → 选路径 → 打开 PNG 确认高过一屏；再把窗口拖窄重复一次，确认宽度跟着变。
