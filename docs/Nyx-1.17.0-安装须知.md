# Nyx 1.17.0 安装须知（安装器行为、已知风险与限制）

> 适用对象：安装器维护者、发版负责人、测试同学。
> 本文记录 Windows 安装包（NSIS）的**实际行为**与**已知风险**，均来自 1.16.0 安装器实现阶段的实测（本机 Windows 10 Pro 26H2 内部版本 26300 / x64）。发版前请通读第三节。

---

## 一、静默参数

| 场景 | 命令 | 说明 |
|---|---|---|
| 静默安装到默认目录 | `Nyx-Setup-x.y.z.exe /S` | 默认装到 `%LOCALAPPDATA%\Programs\Nyx`（每用户安装，无需管理员） |
| 静默安装到指定目录 | `Nyx-Setup-x.y.z.exe /S /D=D:\Apps\Nyx` | **`/D=` 必须是最后一个参数，且路径不能加引号**；`/D` 指定的就是安装目录本身，安装器**不会**再追加 `Nyx` 子目录 |
| 静默卸载（保留个人数据） | `"<安装目录>\Uninstall Nyx.exe" /S` | 程序目录、注册表项、快捷方式会被清除，`%APPDATA%\Nyx` 保留 |
| 静默卸载（连个人数据一起删） | `"<安装目录>\Uninstall Nyx.exe" /S /DELETEAPPDATA` | 额外删除 `%APPDATA%\Nyx` 与 `%LOCALAPPDATA%\Nyx`，**不可恢复** |
| 图形界面安装/卸载 | 直接双击 | 交互模式下卸载会弹出「是否同时删除个人数据？」询问，默认选择「否（保留）」 |

`/S` 静默模式下**不会出现任何页面**（包括环境检查页），因此静默安装不显示阻断项，请先用交互模式确认环境。

## 二、安装器的实际行为

1. **环境检查页**位于「选定安装位置」之后、「安装进度」之前，逐项显示：系统版本与内部版本号、架构、目标目录写权限、目标盘剩余空间、内核依赖、运行库、安装类型（全新/升级/修复/降级）、个人数据目录。
   - 阻断项：内部版本 < 17763、目标目录不可写、目标盘剩余 < 1536 MB。**有阻断项时「安装」按钮被禁用**（不是用 Abort 拦页面，所以「上一步」始终可用，可以返回改目录）。
   - 提醒项：内部版本 < 19041、目标盘 < 2560 MB、检测到 Nyx 正在运行、检测到已装版本比当前新（降级）。
   - 「重新检测」按钮就地重跑全部检测；「打开依赖下载页」会**真实打开系统浏览器**。
2. **安装报告**：每次安装（含静默）都会重写 `%APPDATA%\Nyx\install-report.txt`（UTF-16LE + BOM），内容包括时间、安装器版本、安装模式、安装目录、系统与构建号、架构、目标盘剩余、旧版本、内核版本、完整性检测结果、个人数据目录、静默参数说明、卸载命令、安装器路径。完成页的「查看安装报告」复选框（默认不勾选）可以打开它。
3. **升级 / 修复**：检测到已装版本 → 覆盖安装，报告标注「升级安装」或「修复安装」。**任何安装路径都不会删除 `%APPDATA%\Nyx`**。
   - 同版本 → 「修复安装」；旧版本 → 「升级安装」；已装版本更高 → 「降级安装」并给出提醒（不阻断）。
   - 升级时由 electron-builder 模板先静默调用旧卸载器（`/S --updated`），旧卸载器最多重试 5 次；这一步失败不会中断新版本安装，但可能留下旧版残留目录。
4. **完整性检测**：安装文件复制完成后，若 `resources\integrity.json` 存在，安装器会执行
   `"<安装目录>\Nyx.exe" --verify-integrity --report="%APPDATA%\Nyx\integrity-check.txt"`，
   退出码 0 记「通过」，非 0 记「未通过（退出码 N）」，**任何情况下都不中断安装**；若包里没有 `integrity.json`，报告记「未执行（安装包内没有 integrity.json）」。
5. **完全卸载**：先结束 Nyx 进程，再删快捷方式、`<安装目录>\updates`、程序文件、注册表项；个人数据仅在图形界面确认或带 `/DELETEAPPDATA` 时删除，同时清理 `%LOCALAPPDATA%\Nyx` 与临时目录下的 `nyx-*`。
6. **安装目录默认值**：`%LOCALAPPDATA%\Programs\Nyx`（每用户）。安装器声明为每用户安装，不需要管理员权限；若手动指定到 `C:\Program Files\Nyx` 这类需要提权的目录，检查页会判定「无法创建或没有写入权限」并阻断。

## 三、已知风险与限制（发版前必读）

### A. 发布前必须核对
1. **安装包未做数字签名**：Windows SmartScreen / 浏览器下载会有「未知发布者」告警，用户需要多点一次「仍要运行」。若本轮要求干净体验，必须先解决代码签名。
2. **`resources/integrity.json` 依赖构建钩子**：它由 `build/after-pack.js`（`package.json` 的 `build.afterPack`）生成。若打包流程跳过了 afterPack，安装报告里完整性检测会显示「未执行」，用户侧也就失去了安装后自检能力——发版前请用正式命令构建并抽查报告。
3. **内核版本号是写死的**：检查页显示的 mihomo 版本来自 `build/installer.nsh` 里的常量（当前 `v1.19.31`），不会自动跟随 `vendor/mihomo/VERSION.txt`。**升级内置内核时必须同步改这个常量**，否则检查页会显示过期版本号。
4. **应用版本号不要和安装器逻辑混用**：报告里的「安装器版本」取自构建时的 `version` 字段，发版前统一升版号后再构建，否则报告与产物名会不一致。

### B. 使用限制（属正常行为，但用户会问）
5. **静默安装不带环境检查**：`/S` 会跳过所有页面，机器不满足条件（如系统过旧、磁盘不足）时不会拦截，只会在复制文件阶段失败或装出一个不完整的目录。
6. **`/D=` 语义容易误解**：它指定的就是最终安装目录，不会自动加应用名子目录；参数必须放最后、不能加引号，否则会被忽略并装到默认目录。
7. **桌面路径可能被重定向**：部分机器/策略会把桌面移到非默认位置（实测本机桌面不在用户配置目录下）。安装器与卸载器都按系统 Shell 上下文处理，已验证可用；但如果第三方清理工具搬走了 `.lnk`，卸载时不会再去追。
8. **卸载后 `%APPDATA%\Nyx` 会保留安装报告和内核/缓存数据**：这是设计选择（防止误删书签、历史、设置、扩展）。要彻底清干净必须显式 `/DELETEAPPDATA` 或在图形界面里选择删除，且**不可恢复**。

### C. 尚未验证 / 只在部分场景验证
9. **「打开依赖下载页」按钮未经自动化实点**（点击会真的拉起浏览器），只核对了按钮存在与调用路径。
10. **交互式卸载的「是否删除个人数据」弹窗无法自动化验证**（需要人工点 MessageBox），静默分支已实测通过。
11. **「降级安装」（已装版本比安装包新）分支未实测**：只验证了全新、同版本（修复）、旧版本（升级）三条路径；降级分支的判定代码与前三者共用，但提示文案未在真机跑过。
12. **内核依赖缺失的场景未实测**：正常安装包都带内核，只有包内缺 `vendor/mihomo` 时才会出现「内核缺失」警告并指向下载页，该分支未在真实残缺包上跑过。

### D. 环境相关的坑（排错时先看这里）
13. **`ELECTRON_RUN_AS_NODE=1` 会导致完整性检测误报**：该环境变量会让 `Nyx.exe` 按纯 Node 运行，`--verify-integrity` 变成未知选项并以退出码 9 失败，报告会写「未通过（退出码 9）」。安装器已在自己的进程内临时清除该变量（只影响安装器拉起的子进程，不改系统设置）；**但如果 CI 或用户机器上长期设置该变量，其他外部校验脚本仍会踩坑**。
14. **完整性检测退出码语义**：0 = 与清单一致；1 = 检测到异常；其它值（含 9）= 参数不可用/无法检测。判读报告时不要只看「未通过」，要连退出码一起看。
15. **卸载残留空目录（已修复，勿回退）**：NSIS 卸载器模板会 `SetOutPath $INSTDIR`，导致卸载器进程的当前目录停在安装目录，Windows 不允许删除进程当前目录，于是 `RMDir /r $INSTDIR` 删不掉目录本身。修复方式是卸载初始化时先 `SetOutPath "$TEMP"`。**改动卸载流程时不要移除这一行**。
16. **卸载注册表项名不是 appId**：electron-builder 用的是 `UUID.v5(appId)` 形式的 GUID（本产品为 `ae30b98a-8a1a-5223-86c6-e808d0ff0ca1`），位于 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\<GUID>`。验收脚本、支持文档不要再按 `com.nyx.browser` 去找。
17. **安装目录写权限检测是「真写一次文件」**：检查页会在目标目录创建并删除一个临时文件；若杀软在此期间锁定目录，可能误报为不可写，点「重新检测」重试即可。

### E. 维护者约束（改 `build/installer.nsh` 前必看）
18. **makensis 以「警告即错误」运行**：electron-builder 给 makensis 带 `-WX`，6001（变量未引用）、6010（函数未引用）这类警告会直接让构建失败。安装器与卸载器是**两个独立编译 pass**，所以安装器侧的函数和变量必须包在 `!ifndef BUILD_UNINSTALLER` 内，卸载器侧的（如删除数据开关）必须包在 `!ifdef BUILD_UNINSTALLER` 内。加代码后务必重跑一次完整构建。
19. **自定义页里不能用 `${MUI_HEADER_TEXT}`**：本文件的 include 位置早于 MUI2 的定义点，编译期取不到 `$mui.Header.*`。改页面标题请沿用现有做法（对父窗口 1037/1038 子控件发 `WM_SETTEXT`）。
20. **安装报告的 BOM 不能用 `$\uFEFF`**：makensis 不认这个转义，必须 `FileWriteWord 0xFEFF` 后再逐行 `FileWriteUTF16LE`，换行要显式写 `$\r$\n`。
21. **页面布局用百分比**：静默模式下页面回调根本不执行，无法在自动化里量到控件尺寸，所有自定义页控件都按百分比定位，改布局时不要写死像素高度。
22. **检查页会自己补安装目录子目录**：模板的目录补齐回调在「安装进度」之前才执行，而检查页更早，所以检查页里自己做了「末段是否已是应用目录名」的判断。改动这段逻辑要同时确认交互安装与 `/D=` 静默安装两种布局。
23. **自删逻辑只针对内置更新**：只有当安装器本身位于 `<安装目录>\updates` 时，安装完成后才会延迟删除安装器自身，避免误删用户从浏览器下载的安装包。

## 四、排错速查

| 现象 | 排查方向 |
|---|---|
| 报告写「完整性检测：未通过（退出码 9）」 | 检查 `ELECTRON_RUN_AS_NODE` 环境变量；确认 `--verify-integrity` 已在该版本实现 |
| 报告写「完整性检测：未执行（安装包内没有 integrity.json）」 | 构建没有走 afterPack，重新用正式打包命令构建 |
| 卸载后安装目录还在（空目录） | 卸载器当前目录未离开安装目录，确认 `customUnInit` 里的 `SetOutPath "$TEMP"` 没被删 |
| 装完数据没了 | 只可能是卸载时选了删除或带了 `/DELETEAPPDATA`；安装/升级/修复路径都不会删数据 |
| 静默装完不在指定目录 | `/D=` 不是最后一个参数，或加了引号 |
| 安装按钮点不动 | 环境检查页有阻断项，按提示处理后点「重新检测」 |

安装报告固定位置：`%APPDATA%\Nyx\install-report.txt`；完整性明细：`%APPDATA%\Nyx\integrity-check.txt`。
