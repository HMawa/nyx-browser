## 一、这一版修的是什么

一句话：**换掉一条已经没人维护的运行时线，并且把换内核之后悄悄坏掉的地方补回来。**

1.17.2 的已知边界里写着「Chromium 150 分支落后，得整条运行时升级才根治」。
这一版把这件事做了：Electron 43.8.10 → 45.3.2，Chromium 150 → 156。
代价立刻显现——**Electron 45 把剪贴板读写改成了异步**，两处功能静默失效。
所以这一版的重点不是"升了个版本"，而是**升级之后怎么保证坏了能看见**。

## 二、逐项与理由

### 1. Electron 43.8.10 → 45.3.2

- **为什么跳 44 直接到 45**：44.11.3 只是再走一条同样会被上游甩开的支线；
  「根治分支漂移」只有跳到当前稳定线才成立。
- **踩到的真相**：Electron 45 的 `clipboard.readText()` 返回 **Promise**，
  `clipboard.availableFormats` 直接没这个属性了。表现为两处静默坏掉：
  ①「剪贴板里的网址会成为一条地址栏建议」——`String(promise)` 是 `[object Promise]`，
  匹配永远失败，建议永不出；② 失败页「复制详情」——回读校验抛
  `readback.includes is not a function`，界面只显示一句看不懂的报错。
- **做法**：整个主进程只留两个底层原语（`rawClipboardRead` / `rawClipboardWrite`），
  上面套一层兼容读写；**启动时探测一次形状**，异步形状记 info、退回同步记 warn。

### 2. 剪贴板兼容层收口

- 从「能跑」到「能自己说清楚」：`probeClipboardShape()` 在 `bootstrap()` 里跑一次，
  诊断里留下 `CLIPBOARD_API_SHAPE`（本次真机安装后实测：
  `{"level":"info","code":"CLIPBOARD_API_SHAPE","extra":{"electron":"45.3.2"}}`）。
- 同步回退只告警一次（`CLIPBOARD_SYNC_FALLBACK`），不会每查一次地址栏就刷一条日志。
- 写失败会带着原因抛给调用方（`CLIPBOARD_WRITE_FAILED`），不再"写不进去也算成功"。

### 3. 离线快照：小图存本体，结构不再丢

- 图片策略：最多 **6 张**、单张 **≤120 KB**、一页合计 **≤480 KB**；
  超限的只留一句说明。**不存 Cookie、不存表单内容**，隐私模式仍然从不写入。
- **修掉一个真 bug**：抓取回调原来只把正文行传进快照，v2 的
  blocks / images / skippedImages 全被丢掉——快照悄悄退化成一堆段落，
  图片说明也没了。这类"数据结构升级了，写入路径没跟上"的洞，靠端到端断言才抓得到。

### 4. 页面摘要：被拦下的站点点一下就能查

- 以前只报数（「有 N 个请求被拦下」），用户没法继续。
- 现在摘要里逐条列出被拦下的站点，点一条就把工具箱切到抓包页、按该域名筛好。
- 事件式接线（`nyx:toolbox-focus-net`）：摘要不直接改工具箱内部状态。

### 5. 安装器 e2e 常态化

- `dist\legacy\` 归档 1.16.0 与已发布的 1.17.2；`--cross` 不带 `--from` 时
  自动选最老的归档包，并打印"选了哪个、共几个"。**没有归档就明说怎么办**，不静默降级。
- 新增 `scripts/verify-release-gate.js`（13 项静态守卫）：门禁被绕过、失败没中止、
  跳过没打印，都会被断言抓到。

## 四、这一轮踩到的坑

1. **Electron 二进制下不下来**：`node node_modules\electron\install.js` 挂 20 分钟不动。
   正解是先 `HEAD` 探活镜像（`200 len=158318730`），再手动把 zip 塞进
   `%LOCALAPPDATA%\electron\Cache`，然后跑 install.js——158 MB / 84.5 秒搞定。
2. **`npx electron -e "..."` 弹「Unable to find Electron app」**：Electron 把 `-e`
   后面的字符串当 app 路径。查版本用 `dist\electron.exe` + `ELECTRON_RUN_AS_NODE=1`。
3. **断言被自己的注释绊倒**：`verify-runtime-compat.js` 数 `clipboard.readText()`
   调用点时，把注释里的示例也数了进去（3 处）。断言前必须先剔注释行。
4. **`verify-all.js` 的项数标签与真实项数会脱钩**：每加断言都要同步注释、STEPS、
   台账三处，否则"看起来 503 项"只是个数。
5. **同一个文件多组改动的提交拆分**：`src/main.js` / `renderer.js` / `style.css`
   各混了剪贴板、快照、摘要三组改动，按关键词把 hunk 分桶后逐组 apply；
   相邻 hunk 会互相带上下文，顺序错了就 `patch does not apply`。

## 五、已知边界（不在这一版解决）

- **安装包无 Authenticode 签名**：发布者身份无法验证，只做完整性（sha256）校验。
- **离线快照不是页面原貌**：保留结构与小图，但样式、字体重排、交互都不会恢复。
- **快照只覆盖当前活动标签**：后台标签的正文不会被预先缓存。
- **跨版本 e2e 的门禁基线是"最老的归档"**：归档被清掉（留档只保 3 份）后，
  基线会变成次老那一版，跨度随之变窄。
- **外部接入模式（CDP）审计仍不完整**：只覆盖经过浏览器的部分，与内核升级无关。

## 六、升级方式

- 应用内「检查更新」（启动 8 秒后也会自动检查一次）；
- 或直接运行 `dist\Nyx-Setup-1.17.3.exe`（覆盖安装，保留用户数据）；
- 降级回 1.17.2：`updates-archive\1.17.2` 里留档完整，用 `make-release --restore` 回写更新源。
