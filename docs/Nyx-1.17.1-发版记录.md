# Nyx 1.17.1 发版记录

> 发版日期：2026-11-14　｜　上一版：1.17.0（2026-11-11）
> 一句话：**把「浏览器交给 agent」这件事做完整，并把恢复链路修好——设置改成标签页、失败页说人话、下载真的能下、agent 有眼睛和刹车、后台标签会休眠。**

---

## 1. 这一版解决什么

1.17.0 是「安装链路」版本；1.17.1 是**可用性与安全边界**版本。来源是外部实测清单（12 项，`Nyx浏览器v1实测修复清单.md`）与 agent 化清单（A–G 项，`Nyx浏览器Agent化实现清单.md`）。

清单定调的两句话决定了这一版的取舍：

- **「常规可用性已经及格了，除了下载以外」** → 下载是最高优先级，且它原来是**静默失败**。
- **「把页面信息和所有按钮给 agent，不让他靠截图去猜」** → agent 的眼睛必须是结构化数据，不是图像。

## 3. 逐项说明（只写「为什么这么改」）

### 3.1 下载为什么「全都报废」（A1）

`will-download` 里先 `event.preventDefault()` 再异步弹保存框，拿到路径后 `item.setSavePath()` —— Electron 里 `preventDefault()` 就是**取消**，`DownloadItem` 随即销毁，后续 `setSavePath` 抛 `DownloadItem used after being destroyed`，被空 `catch` 吞掉。默认配置 `downloadAsk: true`，所以**全新安装 100% 命中**。

改法：保存对话框改同步（`showSaveDialogSync`）后 `setSavePath`；失败必给中文提示；新增下载中心记录每个文件的大小、落点、模式、失败原因与平均速度；隐私分区下载改成「明确拒绝 + 告诉用户怎么下」。

### 3.2 「隐私模式悄悄变直连」（A2）

代码里其实**没有**隐私→直连的路径（`sessions.setLink` 硬拒绝）。用户看到的是三处「看不见」：启动时代理不可达会回落普通模式、隐私模式下代理类失败**零提示**、提示在外壳未就绪时被丢掉。

改法：把判定抽成纯函数（`link-guard` + `agent-sites` 同款思路），隐私模式不可达时只告知不降级；`notifyNotice` 加队列，外壳 `did-finish-load` 后补发。

### 3.3 设置为什么从弹窗改成标签页（B4+B5）

两个入口（齿轮 + 工具箱「页面」页签）＋独立弹窗，用户找不到也记不住。改成主窗口里的应用页标签：`kind='settings'` 单实例复用，重复点只切回同一个标签；`nyx:settings:section` 负责深链到某个分区（失败页「查看诊断」直接跳诊断页）。

### 3.4 agent 的「眼睛」为什么不给截图（B）

截图让 agent 靠坐标猜：分辨率变化、页面滚动、懒加载都会让它点错，而且**点错了没人知道**。改成 `readPage` 返回结构化数据 + **稳定 id**（同一页面两次读同一元素 id 必须一致，元素消失明确报 `ELEMENT_NOT_FOUND`）。`screenshot` 降级为「人工辅助」。

### 3.5 为什么所有动作必须走同一条通道（C + D + E）

留痕、权限、急停三件事有一个共同前提：**它们得知道「每一次动作」**。只要有一条路径绕过通道，审计就会漏、急停就拦不全。所以 `actions.js` 只保留执行能力，HTTP 与 MCP 都只能调 `dispatch()`。

### 3.6 为什么外部接入要重启、且必须两次确认（A）

Chromium 的 CDP 端口**只能在进程启动时打开**，没有运行时开关。所以「切换」本质是「改下次启动的参数」，界面必须如实说「重启后生效」。外部接入的审计从设计上就不完整（第三方进程可以直接调 CDP），所以常驻一条「审计不完整」标识，且切换要两步 + 勾风险，**不允许一键完成**。

### 3.7 为什么断网要单独判（G）

断网时如果按「代理不可达」处理：普通模式会把链路改成直连，网络恢复后就成了「代理模式却在直连」，用户毫不知情；隐私模式会反复喊「代理已断开」，把「没网」说成「代理坏了」。所以 `online === false` 时链路一律不动，只发一条 warn 通知 + 横幅。

### 3.8 标签休眠的边界（G）

闲置 30 分钟（可调/可关）释放后台标签的渲染进程；**当前标签 / 被 agent 操作过的标签（2 分钟保护期）/ 设置页永不参与**。诚实边界：休眠等于卸载页面，未提交的输入与滚动位置会丢，点回来按原地址重新加载。

## 5. 坑与决策

1. **假通过比失败更贵**：`#pe-hints` 里残留上一条错误的建议，让「HTTP 404 有建议」这条断言一直是绿的；清空后才发现 HTTP 状态码从来没有建议列表。同类还有：断言写死在 3 条（多一条历史记录就红）、用 `window.nyx.foo = stub` 打桩（contextBridge 是冻结代理，静默失效）。
2. **测试卡死要先怀疑模态对话框**：站点授权未命中会弹确认框，自动化里没人点 → 整个脚本挂到超时。修法不是放宽断言，而是让测试环境把测试站点登记进白名单（真实用法），并用 `AbortSignal.timeout` 给每个请求兜底。
3. **`TabManager.active` 是 getter**，写成 `active()` 永远得 `undefined`，表现为「当前没有打开的页面」——类型不报错，只有端到端能抓到。
4. **`String.raw` 是页面注入脚本的硬要求**：普通模板串会把 `/\n+/` 的 `\n` 变成真换行，脚本语法错误只在运行时暴露。
5. **PowerShell 不许碰源码**：`node -e "...replace(&&...)"` 会被 pwsh 当自己的语法解析；`Get-Content/Set-Content` 按 GBK 解码会把中文源码毁成乱码（本项目发生过一次）。
6. **主进程 handler 的返回体里绝不能嵌 Promise**：`getHardwareStatus()` 返回 Promise，被塞进返回对象后 `ipcRenderer.invoke` 既不 resolve 也不 reject，界面永远「读取中…」。

## 6. 已知边界（不假装完成）

1. **外部接入模式的审计天生不完整**：只看得到经过浏览器的部分，界面常驻标识，不做 CDP 侧二次录制。
2. **急停掐不断已在执行的单条脚本**：`executeJavaScript` 无法在 V8 中途中断，保证的是「不再派发下一条 + 立刻拒绝新动作」。
3. **页面摘要只覆盖当前活动标签**，正文抽取是启发式（行去重 + 关键词打分），不接生成式接口。
4. **断网判定依赖系统报告的在线状态**：虚拟网卡/驱动误报有网时仍按有网走原规则（宁可报代理不可达，也不假装断网）。
5. **标签休眠会丢未提交输入与滚动位置**（卸载页面的代价），当前标签/agent 驱动/设置页不参与。
6. **C2 的 CVE 结论仍标「待联网复核」**：本轮没有联网核对公告，文档里如实写着待复核，没有抄未核实的编号。
7. **站点名单只做域名级**：`prefix` 模式已在数据结构里预留，但界面上还只能填域名。
8. **A3 只做测量不做传输优化**：本地实测 Nyx 下行约为同机 Node 的 61%（467.7 vs 763.4 MB/s），属 Chromium 网络栈开销；深挖要动隐私出口，属产品取舍。
