## 1. 这一版想解决什么

在此之前，Nyx 的网络接入界面用的是**工具作者视角**：代理中心、内置代理内核、订阅、节点、测速、分流规则。

对一个在校园网里、按学校网络中心给的说明填地址的人来说，这些词等于要他先学会一套他不需要的概念。
1.19.0 的做法是加一层**外壳**：同样的网络能力，换一套按「你怎么接入」组织起来的说法，
并让用户第一次打开时就能选自己是哪一种接入方式。

**只改呈现层。** 内核、订阅、端口、分流、代理链路一行未动——这也是这一版能一天内做完并敢发的原因。

## 2. 三档接入方式

| 档 | 显示名 | 默认给谁 | 界面 |
| --- | --- | --- | --- |
| `campus` | 校园网络接入 | 新装默认 | 换词 + 三段式引导 |
| `enterprise` | 单位网络接入 | 手动选 | 与校园**同一张词表**，只有显示名与说明不同 |
| `custom` | 自定义服务端 | 老用户升级默认 | 与 1.18.2 **逐字相同** |

**为什么保留 `enterprise`（2026-11-18 的决定）**：实测 `termsFor('campus')` 与 `termsFor('enterprise')`
28 个词条**逐字相同**，差别只有 `IDENTITY_LABELS` 与 `IDENTITY_NOTES` 两处。
即「单位档」不是第三张术语表，是同一张表的第二个标签；砍掉省两句文案、却要多付一次改动与复测，
而且它是最高频的真实场景（公司/单位网）。为此新增断言第 29 项把这条锁死：**词条不许分叉**。

回滚路径：设置页顶部身份选择器切回「自定义服务端」，界面立即逐字还原。

## 5. 坑与决策

1. **断言写死文案 → 真回退**：外壳把「更多」菜单的「代理中心」换成「接入通道」，`verify-ui-polish.js` 里 B1 那条断言写死 `/代理中心/` 直接红。
   修法不是放宽文案断言，而是给 `#more-proxy` 加 `data-net-section="network"`、断言改判「这一项指向 network 分区」——**说法随身份变，按字面判早晚还会红**。
2. **语料只扫两个文件等于没扫**：原第 25 项只扫 `proxy-center.js` + `settings.html`，别的渲染层文件写新文案不会被查。
   本轮扩到全部 `src/renderer/*.{js,html}`（2312 条字面量），残留 0。
3. **「单位档」的成本被高估**：决策前先 `termsFor()` 对比，28 条差异 0 条——省下了砍一层要付的改动与复测。
4. **耗时不能当版本特征**：同一套 1151 项脚本，轻载 545 秒、本机 801 秒。文档只记项数与通过数，耗时标注负载。
