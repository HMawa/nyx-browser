### A4 失败页
- 状态：**完成**（`d33be32` 功能 + `018780b` 排版与建议补齐）。
- 现象：失败只在设置里显示，主界面空白无提示。
- 做法：主进程 `TabManager` 记 `tab.loadError`，`layout()` 里 `visible = activeId && !loadError`（隐藏坏视图），失败信息随状态快照下发；外壳 `#page-error` 浮层渲染「错误码 + 中文原因 + 地址 + 可执行建议」，三个按钮：重试（失败页里点重试走 `retryLoadError`，用 `requestedUrl` 重发）、打开诊断（设置窗口直接落到诊断分区，`openSettings('diagnostics')` + `nyx:settings:section` 推送）、复制详情（7 行文本进剪贴板）。错误码映射两套：网络层 `describeLoadError` 24 个 + `ERROR_HINTS` 17 个，HTTP 层 `HTTP_STATUS_REASONS` + `buildHttpHints`。
- 验证：`npm run verify` **137 项全绿**（69 + 57 + 11，106s）。实测证据：连接被拒 → `ERR_CONNECTION_REFUSED / 这一页没能打开 / 连接被拒绝，目标端口没有服务`；404 → `HTTP 404 / 页面不存在 / 地址对应的页面不存在（可能已被删除或链接写错）（Not Found）`；点重试 → `{"visible":false,"loadError":null}` 并真的加载成功；复制 → 剪贴板 `Nyx 加载失败：页面不存在（HTTP 404）…`；打开诊断 → `{"nav":true,"panel":true}`。
- **踩到的假通过（重要）**：404 用例断言「有建议列表」，旧代码在无建议时只 `hidden` 不清空 DOM，`#pe-hints` 里残留上一条网络错误的两条 `<li>`，于是断言一直是真通过；把「无建议时清空」补上后立刻暴露真缺陷（HTTP 状态码从无建议）。教训：**列表类 UI 的断言要断言"当前渲染的内容"，不能只看元素数量；不清空容器会让旧内容顶替新内容通过测试。**

### A2 不静默降级（完成）
- 现象：开 clash 后刷新几次，全隐私模式自己变回直连（不稳定复现）。
- 取证结论：代码里**根本没有「隐私 → 直连」的路径**（`sessions.setLink()` 对 `private+direct` 硬拒绝并 warn；`getLink('private')` 恒为 `proxy`）。真正让用户觉得"自己变直连了"的是三件事：① 启动时上次是隐私模式但代理不可达 → `restoreLastMode()` 主动回落普通模式 + 直连；② 隐私模式下代理中途挂掉时 `handleProxyLoadFailure()` 第一行 `if (sessions.getMode() !== 'normal') return;` **直接返回，前台零提示**，页面只有一个光秃秃的 ERR 码；③ `notifyNotice()` 只判 `isDestroyed()`，窗口还在但外壳页面没 `did-finish-load` 时 `send('nyx:notice')` 直接丢——启动那条"已回落普通模式"的提示经常就是这么消失的。
- 改动：
  - 新增 `src/core/link-guard.js`（纯逻辑，零 Electron 依赖）：`PROXY_FAILURE_CODES`（-130/-102/-101/-104/-118/-105）、`isProxyFailureCode()`（只认 number）、`decideProxyFailureAction({mode, link, reachable, errorCode, host, port, error})` → `{action, notice, reason}`；三种动作 `none` / `fallback-direct`（仅普通模式）/ `notify-private`（隐私模式，文案含「隐私模式不会降级为直连…需要直连请手动切到普通模式」）。缺参/脏参一律按保守默认走，不抛异常。
  - `src/main.js`：`handleProxyLoadFailure()` 改为调用该纯函数（删掉 `mode !== 'normal'` 早退）；隐私分支补 `diagnostics.error('PRIVACY_PROXY_DOWN', …)` + `modeEventLog.record({from:'private',to:'private',ok:false,code:'PRIVACY_PROXY_DOWN'})` + `notifyNotice()`；普通转直连分支同样补 `diagnostics.warn('PROXY_FALLBACK_DIRECT', …)` 与模式事件；主进程原本自带的那张错误码表改为只引用 `link-guard`（单一真相）。
  - `src/main.js` 提示通道：`runtime.shellReady` + `runtime.pendingNotices`（FIFO），`notifyNotice()` 未就绪时入队，`did-finish-load` 里 `flushPendingNotices()` 按顺序补发；启动提示改为 `if (startupNotice) notifyNotice(startupNotice)`，不再单条覆盖。
- 验证：`npm run verify` **153 项全绿**（69 + 61 + 12 + 11，120s）。新增 `scripts/verify-link-guard.js` **12 项**（6 个链路码逐个验证隐私模式永不产生 `fallback-direct`、隐私不可达文案必须含「不会降级为直连」与真实端口、普通模式转直连文案、脏参不抛异常、字符串码不算命中，外加 3 条静态守卫锁住 `sessions` 的硬拒绝 / 主进程的隐私分支 / 提示排队逻辑）；`verify-ui-polish.js` 新增 1 项：主进程那种 `level=error / PRIVACY_PROXY_DOWN` 通知落到界面必须是可见的 `.notice.notice-error` 且标题含「未降级」。
- 提交：`fix(A2): 隐私模式代理断开时明确告知且绝不降级，提示不再因外壳未就绪而丢失`。
- 遗留：`restoreLastMode()` 的启动回落行为**未改**（代理不可达时仍回落普通模式）——这是刻意的：无代理时强行停在隐私模式等于让用户开不了网页；但它现在有提示 + 诊断 + 模式事件三条留痕，且文案明说"已回落普通模式（直连可用）"。

### A1 下载
- 现象：灰度/普通/暴力都下不了文件，前台零提示（原话「文件下载这一块儿全都报废了」）。
- 已掌握的关键事实（1.16.0 线实测）：`will-download` 里 `event.preventDefault()` 之后再异步 `setSavePath` = 下载被取消，`setSavePath` 抛 `DownloadItem used after being destroyed` 被空 catch 吞掉。**必须同步定落点**。
- 技术落点：同步 `setSavePath`（或 `showSaveDialogSync`）+ `item.on('updated'/'done')` → 下载栏（进度/速度/剩余/失败原因/落点/打开目录）+ `Ctrl+J` 历史；隐私模式下载改为明确提示而非静默拦。
- 验收：5 种场景（<1MB / 10MB / 500MB / 短链重定向 / 403-404）全部有明确结果。
