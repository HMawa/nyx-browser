# Nyx 版本变更总览（CHANGELOG）

> 汇总 1.3.0 → 1.17.9 二十六个版本的变更、验收数字与踩过的坑。
> 本文件是索引，**原始发版记录保留在 `docs/Nyx-<版本>-发版记录*.md`**，细节以原文为准。

## 怎么读

- 版本顺序：**最新在最前**（1.17.0 → 1.3.0），每版一节 `## 版本号 · 日期`。
- 每节结构固定四块：**主题**（一句话）→ **变更**（表格）→ **验收**（断言数 / 体积 / 校验值）→ **坑与决策**（当版沉淀的 1–3 条经验）。
- 发版命令一行：`npm run dist` → `node scripts/make-release.js --release --prune`（卡执行策略时用 `& 'C:\Program Files\nodejs\npm.cmd' run dist`；1.17.4 起打包走 `node scripts/build-signed.js --config.directories.output=dist`，会先查证书有效期再签）。
- **「验收断言」这一列是当时的统计口径，不是今天的口径。** 早期版本只有 3 个脚本（地址栏 / 界面 / 打包冒烟），
  后来每补一类问题就多一个纯逻辑脚本（链路 / 下载 / 图形 / 安全基线 / 外壳防护 / 录屏 / 动作通道 / 页面读取 /
  agent 审计 / 站点授权 / 接入模式 / 页面摘要 / 标签生命周期 / 标签休眠 / 断网判定 / 离线页面缓存 /
  运行时兼容 / 发版门禁）。
  所以 1.16.0 写 122、1.17.1 写 431、1.17.3 写 503，**不代表这之间只多了几十项功能**，而是「同一批功能被更多脚本盯着了」。
  跨版本比较请看各自 `docs/Nyx-<版本>-发版记录*.md` 里的明细，别拿这一列做趋势。

**主题**：12 项改进清单剩下的九项（A4/A5/C2/C1/B1/B2/D2/D1/D3）+ 一次回归基础设施加固——工具栏只留四个主路径、agent 状态灯能就地急停、首装一次引导、两套新主题。详见 `docs/Nyx-1.17.9-发版记录.md`。

**验收**：`npm run verify` = **32 个脚本 / 756 项 / 447 秒**全绿；打包前签名 38/38（证书剩 1826 天）；完整性 9/9（清单 1.17.9）；冒烟 11/11；安装器 e2e **56/56**（升级基线 1.17.8）；发版收尾自动量差分 1.17.8 → 1.17.9 = 243 块 / 命中 0 / 0.00%；真机静默安装 FileVersion 1.17.9、升级路径 `onboarding.json` 写 `pending:false`（不弹引导）、启动 5 进程、诊断四条正常。体积 121.4 MB（127,250,504 字节），sha256 `507da5fc90043701100cb5cfeb750a12dd7a804cfdd8c62dfa804076ebd68a16`。

**坑与决策**：① 设置页 `init()` 里 `await` 一个永不返回的 IPC（`nyx:hardware:status` 的 PowerShell 探测）会让后续初始化**静默不发生**——必须逐项超时兜住；② `.sec-scroll` 是纵向 flex，卡片铺开会被互相压扁（`max-height` 有值但 `getBoundingClientRect().height` 是 0）；③ `edit` 删整段 HTML 少一个 `</div>` 会让下一个分区变成子节点（探针打出 `displayParent` 才发现）；④ 浅色主题的浅灰字必须实算对比度（奶白 `#8a9299` 2.87:1、海盐 `#7f9099` 2.96:1，都改到 ≥3.3:1）；⑤ 发版构建读的是**工作区** `package.json`，只把版本号写进 index 会导致把上一版重打一遍（已从留档还原 dist 里的 1.17.8）。**已知边界**：字号档位未做（清单写明属独立改造）、`nyx:hardware:status` 根因未治、`AGENT_STOP_SHORTCUT_FAILED` 仍只在诊断里。

## 1.17.8 · 2026-11-15

**主题**：12 项改进清单的首批三项（A1/A2/A3）——设置页变短、摘要不再被压、进程能分辨。详见 `docs/Nyx-1.17.8-发版记录.md`。

**变更**

| 项 | 改了什么 |
| --- | --- |
| A1 卡片折叠 `50ece79` | 设置页 9 个分区约 40 张卡片可逐张收起；**收起态右侧仍显示当前值**（开关「开/关」、下拉选中项、输入框内容、状态卡首项）；只记与默认不同的卡片（新卡片不会因没人记过而被收起）；每个分区有「全部铺开 / 全部收起」；默认「外观、网络」铺开，其余收起 |
| A2 摘要让位 `16e399e` | 打开摘要时标签页让出右侧（`DIGEST_PANEL_W = 402`），工具箱也开着就并排（`applyRightInsets()` 把两份宽度一起交给 `setRightInset`）；IPC `nyx:digest:panel` + `nyx:toolbox-layout` 事件重算。**根因不是 z-index**：标签页与工具箱都是 `WebContentsView`，永远盖在外壳 DOM 上 |
| A3 进程可辨识 `83e6170` | 每个渲染进程注入 `--nyx-kind` / `--nyx-tab` / `--nyx-host`，任务管理器「命令行」列可见；设置 → 诊断 → 进程详情表（PID / 是什么 / 内存，主进程最前、按内存降序、可复制）；休眠唤醒时先清旧 `--nyx-*` 再重建 |

**验收**：`npm run verify` = **24 个脚本 / 675 项 / 237 秒**全绿（界面 121 → 128，新增 `verify-process-args.js` 11 项）；完整性 9/9；签名 38/38（证书剩 1826 天）；冒烟 11/11；真机静默安装 FileVersion 1.17.8。实测量值：收起态 `bodyHeight=0` 且右侧显示「关」、铺开后 144px、工具箱并排时 `inset=862` 且末条可见。

**坑与决策**：① `display:none` 子树里 `getBoundingClientRect()` 全是 0，量高度前必须先点导航切过去；② 卡片增强在 `init()` 里，测试要轮询等 `.info-card[data-fold-id]`；③ `insertBefore` 锚点不能用 `querySelector('.badge')`（可能取到嵌套子节点 → `NotFoundError`），改 `titleEl.nextSibling`；④ 设置页导航项要用 `settings.eval`。**两条诚实边界**：映像名永远是 `Nyx.exe`（Windows 不允许每进程改名）；A2 的「并排」是让标签页缩窄，不是浮层。

## 1.17.7 · 2026-11-15

**主题**：把「界面上写着的东西」和「实际发生的事」对齐——差分数字过期了要说、计划任务没注册要说、名单改了不生效要说、agent 干了什么也要看得见。含第九轮五项与第十轮五项，详见 `docs/Nyx-1.17.7-发版记录.md`。

**变更**

| 项 | 改了什么 |
| --- | --- |
| 差分新鲜度 | `describeDeltaFreshness(report, {currentVersion, staleDays, now})` 五级（没量过 / 没量成 / 配对已变 / 超过 30 天 / 仍然有效）；配对变了直说「它不描述下一次更新」；判定只在主进程做一处。**「重新量一次」按钮第七轮就有**，「加按钮」不成立 |
| 夜间计划任务 | `src/core/nightly-task.js` 统一参数拼法与输出解析（`scripts/lib/nightly-plan.js` 改成转出口）；GBK 解码（`TextDecoder('gbk')`）；**默认不提权**（带 `/RL HIGHEST` 才报「拒绝访问」）；注册与删除都复核，命令说成功但查不到一律算失败 |
| 计划任务界面入口 | 设置页夜间卡加时间输入 + 「注册 / 改时间」+「删掉任务」，装版里没有 `scripts/` 就如实回 `NOT_AVAILABLE`；**仍然不给「现在就跑一次」** |
| 模板导出导入 / 替换 | `nyx-cache-templates` + `version: 2`（不带 mode）；导错 kind、版本更高、结构坏了分别说原因；`applySiteTemplate(..., {mode})` 支持「替换」，逐条报出被换掉的站点、**屏蔽名单原样保留**；可选 `alsoNormal` 顺带套到普通模式那份，两份结果分开报 |
| 动作聚合 | `aggregateAgentActions()` 跳过 `settings`（避免一块各数一次），`deny`/`ok:false` 只计「被拦下或被拒」不进执行次数；「它都干过什么」表格 + 站点分布；动作记录也能导出 CSV（CRLF，被拦下总数只写第一行） |
| 名单是否真生效 | `privateSiteEffective()` 读快照开关与系统加密可用性，不生效时把中文原因接在结果后面并用警告样式显示（原来界面照样说「已并入名单」） |

**验收**：`npm run verify` = **23 个脚本 / 657 项 / 215 秒**全绿；完整性 9/9；冒烟 11/11；安装器 e2e **56/56**（升级基线 1.17.6）；发版收尾自动量差分「1.17.6 → 1.17.7：243 块 / 命中 0 / 0.00%」；`dist/Nyx-Setup-1.17.7.exe` 127,225,416 字节、sha256 `ffb68720c5f26353177efc3870ab6327e9c11c6495d3f77cc72429c08f497e96`；真机静默安装 FileVersion 1.17.7、启动 5 进程 661 MB。

**坑与决策**：① `git apply` 拆不出三桶（`-U0` 没上下文、`-U1` 行号假设），改用「按新增行关键词分桶 + 整段替换 + 与备份 sha256 比对」；② 改实现后旧断言会假红，必须连断言一起改；③ 普通模式那份名单叫 `cacheSitePolicy()`，没有 `normalSitePolicy`；④ 插 check 时吃掉了下一行的 `const failed = …`，改门禁脚本后要立刻跑一次。
