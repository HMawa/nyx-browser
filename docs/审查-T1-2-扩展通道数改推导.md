7 项全 OK，唯一红的是这条"数量"。而它列出来的 13 个通道本身不多不少，正好是

## 2. 取证

1. 改前代码（`scripts/verify-extensions-wiring.js:75-77`）：

```js
const extChannels = [...mainJs.matchAll(/ipcMain\.handle\(\s*['"](nyx:ext:[^'"]+)['"]/g)].map((m) => m[1]);
if (extChannels.length !== 8) problems.push(`扩展 IPC 通道数量异常：期望 8，实际 ${extChannels.length}…`);
```

2. `src/preload.js` 里 `nyx:ext:*` 声明实测 13 条（`listExtensions` / `addExtensionFromDir` /
   `addExtensionFromCrx` / `toggleExtension` / `removeExtension` / `reloadExtensions` /
   `reloadTabsForExtensions` / `openExtensionStore` / `extOnlineCheck` / `extOnlineInstall` /
   `extOnlineUpdateAll` / `extOnlineHistory` / `extOnlineRollback`），与主进程 13 条一一对应。

3. 结论：8 是"扩展在线更新/历史回滚"那批通道上线之前留下的数字。这条断言的原意是
   「别把扩展的 IPC 漏接」，用**总数**表达这件事本身就不对：后来加通道必然红，
   而真漏接一条（13 变 12）反而可能被"数量不等于 8"掩盖成同一条报错，看不出是哪条漏了。

## 3. 改动

`scripts/verify-extensions-wiring.js`（仅此一个文件）：

```js
const extChannels = [...new Set([...mainJs.matchAll(/ipcMain\.handle\(\s*['"](nyx:ext:[^'"]+)['"]/g)].map((m) => m[1]))];
const extInvoked = [...new Set([...preload.matchAll(/ipcRenderer\.invoke\(\s*['"](nyx:ext:[^'"]+)['"]/g)].map((m) => m[1]))];
const extMissing = extInvoked.filter((channel) => !extChannels.includes(channel));
if (!extChannels.length) {
  problems.push('main.js 里没有任何 nyx:ext:* 的 ipcMain.handle：扩展管理器的 IPC 通道一个都没注册');
} else if (extMissing.length) {
  problems.push(`preload 声明了扩展通道但主进程未注册：${extMissing.join(', ')}`);
} else {
  notes.push(`扩展 IPC 通道 ${extChannels.length} 个（preload 声明的 ${extInvoked.length} 个全部已注册）`);
}
```

判据从「数量必须等于 8」换成三条真契约：

1. **不能为 0**：整块 IPC 掉了（比如重构把注册段删了）会立刻红；
2. **preload 声明 ⊆ 主进程注册**：漏接一条就点名是哪一条；
3. 数量只写进 notes 作记录，不再当断言。

## 5. 这条检查能证明什么、不能证明什么

- **能**：preload 暴露的扩展接口与主进程注册的通道对得上，没有"点了没反应"的哑接口。
- **不能**：不能证明通道的行为正确（比如安装真的成功、回滚真的回滚）。
  行为由 `verify-extensions.js`（安装/启用/重启装载）与 `verify-extensions-startup.js`
  （真实启动后分区装载情况）覆盖 —— 后者已在 T1-1 修好，前者见 T1-3 的定性结论。
