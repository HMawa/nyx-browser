# Nyx 1.17.8 发版记录

> 发布于 2026-11-15 下午。上一版 1.17.7（2026-11-15 凌晨）。
> 这一版是「12 项改进清单」的首批**三项（A1 / A2 / A3）**。
> 一句话主题：**把每天都要看的东西变短、把被压住的东西挪出来、把分不清的进程标出来。**

---

## 1. 这一版想解决什么

清单里的 12 条按病根分成四组（A 界面密度 / B 顶栏与动效 / C 体积与启动 / D 引导与主题）。
首批只做 A 组的三条，因为它们是**同一件事的三个面**：屏幕上同时存在的东西太多，且没有主次。

- 设置页有 **9 个分区、约 40 张卡片全部铺开**——找一个开关要滚很久，而多数时候你只是想确认「它现在是开着还是关着」。
- 摘要面板明明打开了，**却被页面和工具箱压住**，看见的只有左上角一条边。
- 任务管理器里一列 `Nyx.exe`，**分不清哪个是主进程、哪个是哪个标签**，出事时没法判断该结束哪一个。

这一版的统一做法：**不新增功能，只让已有的东西可说、可辨、可让位。**

## 3. 逐项说明（为什么这么做）

### 3.1 `08b498d` 卡片折叠：收起之后仍然要看得见值

- 折叠不是把内容藏起来就完了。**收起态右侧显示「当前值」**：开关是「开 / 关」、下拉是选中项文本、
  输入框是填的值、纯状态卡是 `kv-grid` 里的第一项。判断优先级写在 `describeCardValue()` 里，按卡片实际结构试探。
- **只记与默认不同的卡片**：`settingsFold` 存的是「哪些卡片被手动改过」，所以以后新增的卡片不会因为「没人记过」而被收起。
  存成 JSON 字符串是因为 `nyx:ui:prefs-set` 的取值校验只收布尔与字符串——不为了这件事放宽校验。
- 默认态按用户拍板：**常用分区（外观、网络）铺开，其余收起**；每个分区标题右上角有「全部铺开 / 全部收起」。
- 动画用 `max-height` 过渡，但**强制重排一次再切 0**（`void body.offsetHeight`），不用 `requestAnimationFrame`：
  后台标签里 rAF 会被节流甚至不触发，那会把「动画不播」变成「功能坏了」。`prefers-reduced-motion` 下直接切。

### 3.2 `1abd33f` 摘要让位：根因不是层级

- **取证结论**：`.digest-panel` 的 `z-index` 是 40，工具箱 900、通知 1000。但调 `z-index` 没用——
  标签页与工具箱都是 `WebContentsView`，**永远画在外壳 DOM 之上**。这是本项目已知的架构事实（浮层必须独立窗口）。
- 因此正解是**让出宽度**，与工具箱既有的 `setRightInset` 同一套：
  - 主进程新增 `DIGEST_PANEL_W = 402`（380 面板 + 14 边距 + 8 呼吸位）与 `DIGEST_PANEL_GAP = 14`；
  - `applyRightInsets()` 把「工具箱宽度 + 摘要宽度」一起交给 `TabManager.setRightInset()`；
  - 新增 IPC `nyx:digest:panel`，界面侧 `syncDigestLayout()` 根据工具箱是否打开，把面板 `right` 往左挪并加 `.is-beside-toolbox`；
  - 工具箱开关或换宽度时派发 `nyx:toolbox-layout`，摘要跟着重算。
- 结果：**两块并排，都不挡**；最窄窗口下摘要的最后一条也看得见。

### 3.3 `4cb172a` 进程可辨识：把身份写进命令行

- 用户要的是「在系统资源管理器里看到进程详情」，所以**不能只做应用内面板**。
- 做法：给每个渲染进程创建时注入 `additionalArguments`——`--nyx-kind=tab`、`--nyx-tab=<id>`、`--nyx-host=<host>`，
  **任务管理器的「命令行」列**（以及进程资源管理器、`wmic`/`Get-CimInstance`）立刻能看到。
- 应用内再给一张表（设置 → 诊断 → 进程详情）：PID / 是什么 / 内存，主进程排最前、其余按内存降序；
  **PID 与任务管理器一致**，可一键复制。对不上标签的渲染进程标「渲染进程（没对上标签）」，睡着的标签不进表。
- 休眠唤醒时**先清掉旧的 `--nyx-*` 再重建**：休眠期间地址可能变过，留着旧 host 比没有更糟。

**两条诚实边界（已写进界面说明，也写在这里）：**

1. **映像名永远是 `Nyx.exe`**。Windows 不允许每个进程用不同的映像名，也不给应用改名进程的权力——
   所以「进程详情」里说的是**命令行标记 + 应用内映射**，不是改名。不承诺做不到的事。
2. **摘要面板的「并排」是让标签页缩窄**，不是浮在页面上面。如果以后要真浮层，得把它做成独立窗口（另一件事）。
   另外：老标签的进程是旧版本起的，没有 `--nyx-*` 标记，**开一个新标签**就能看到。

## 5. 这一版踩到的坑

1. **`display:none` 子树里量高度全是 0**。先量「铺开后高度」时一直得 0，看着像折叠没生效；
   实际是那个分区还没被激活（`display:none`），`getBoundingClientRect()` 不参与布局。测试里必须**先点导航切过去**。
2. **卡片增强发生在 `init()` 里**（要等偏好、硬件信息回来）。测试若立刻查 `.info-card[data-fold-id]` 会一个都没有 → 必须轮询等。
3. **`insertBefore` 的锚点不能用 `querySelector('.badge')`**。有些卡片的 badge 嵌在子结构里，取到的不是直接子节点，
   直接抛 `NotFoundError: Failed to execute 'insertBefore' on 'Node'` → 改用 `titleEl.nextSibling`。
4. **设置页里的导航项必须用 `settings.eval`**。用外壳 target 会拿到 `null`，报
   `TypeError: Cannot read properties of null (reading 'click')`——`.nav-item` 在设置页那个视图里。
5. **又一次差点用 pwsh 内联 node 改源码**：拼中文字符串直接 `SyntaxError: Invalid or unexpected token`。
   红线 1 的读侧同样适用：改文件只用 `edit` / `write`。

## 6. 已知边界

1. **不含 A4/A5 及其余 7 项**：A4（抓包跟随/独立 + 每标签 500 条）、A5（三色 agent 面板）在 1.17.9；
   C2（量基线）/ C1（无行为变化裁剪）/ B1（顶栏精简）/ B2（边框与动效）/ D2（首装引导）/ D1（接入话术）/ D3（主题）排在其后。
2. **折叠状态是「每台机器各记各的」**：不做云同步，也不进导出。
3. **进程详情只覆盖 Chromium 自己的进程**（主进程 + 渲染进程 + GPU + utility），不接管系统里别的进程。
4. **A2 的让位是「挤窄标签页」，不是浮层**：极窄窗口（< 900px）下摘要会占掉相当比例，这是取舍。
5. **随包的该扩展扩展仍在包内**，C1 的裁剪尚未开始（用户已确认「移出随包、只留源码」这个方向，将在 C1 执行）。

## 7. 升级

- 应用内「检查更新」会自动发现 1.17.8（本地更新源 `%APPDATA%\Nyx\updates` 已写入）。
- 静默安装：`Nyx-Setup-1.17.8.exe /S`，默认装到 `%LOCALAPPDATA%\Programs\Nyx`。
- 回退：`dist\legacy` 与 `%APPDATA%\Nyx\updates-archive` 里保留 1.17.7 / 1.17.6 / 1.17.5，
  直接装旧版即可（数据在 `%APPDATA%\Nyx`，不随版本回退被删）。
- 本版含自签名（`CN=Nyx Self-Signed`）：**能证明包是我打的、也能证明打完没被改过**，
  但**不能**证明「谁打的」，SmartScreen 仍会提示未知发布者。
