# 审查单 · T1-1 扩展启动自检：清掉 ELECTRON_RUN_AS_NODE

- 任务卡：`Nyx-PC主开发交接-1.20-v1.md` §5 T1（扩展验证脚本补档）
- 性质：**脚本自身缺陷**（不是断言过期，也不是产品 bug）
- 状态：已修，脚本 10 项全绿；提交 `fix(ext): 启动自检脚本清掉 ELECTRON_RUN_AS_NODE（红线 10）`

---

## 1. 现象（改前实测）

```
node scripts\verify-extensions-startup.js
共 5 项，失败 2 项
  [PASS] 隔离 profile 预置扩展成功
  [PASS] 索引内 1 条且为启用状态
  [FAIL] 主程序正常退出（退出码 0）
  [FAIL] 启动报告可解析
  [PASS] 主进程无未捕获异常
```

被测进程 stderr 末尾是纯 Node 的崩溃栈尾（`Node.js v24.22.2`），不是 Electron 的启动日志。

## 2. 取证（为什么是这个原因）

1. `scripts/verify-extensions-startup.js:116` 原代码：

```js
const run = spawnSync(electronBin, [ENTRY], { cwd: ROOT, encoding: 'utf8', timeout: 120_000 });
```

没有传 `env`，子进程**完整继承**父进程环境。

2. 本机环境实测：

```
ELECTRON_RUN_AS_NODE=[1]
NODE_OPTIONS=[]
```

3. `ELECTRON_RUN_AS_NODE=1` 会让 Electron 二进制退化成纯 Node 解释器：它会把 `ENTRY`
   当普通脚本执行，脚本里的 `require('electron').app` 拿到的是字符串路径而不是 app 对象，
   于是直接抛错退出 —— 主程序从来没起来，自然「退出码非 0」「报告文件没写」。
   这正是 `AGENTS.md` 红线 10 记的那条坑。

## 3. 改动

`scripts/verify-extensions-startup.js`（仅此一个文件，+15 行）：

```js
const childEnv = {
  ...process.env,
  NYX_USER_DATA: USER_DATA,
  ELECTRON_DISABLE_SECURITY_WARNINGS: '1',
};
delete childEnv.ELECTRON_RUN_AS_NODE;
check('子进程环境已清掉 ELECTRON_RUN_AS_NODE（红线 10）', !('ELECTRON_RUN_AS_NODE' in childEnv));

const run = spawnSync(electronBin, [ENTRY], { cwd: ROOT, env: childEnv, encoding: 'utf8', timeout: 120_000 });
```

两点说明：

- **只删这一个变量**，其余环境原样传递（不搞 `env: {}`，那会把 PATH 之类也抹掉）。
- 加了一条 `check(...)`：把「子进程环境必须干净」这件事本身变成可见断言，
  以后谁再把 `env` 漏掉，第一次跑就红，而不是等一个看起来像产品 bug 的假失败。

## 8. 复核后补齐：弃用 API 也迁了（2026-11-23）

复核意见说得对：只迁 `loadExtension / removeExtension` 就写"新命名空间迁移完成"是不成立的，
`getAllExtensions` 还在用旧写法，内核一旦移除旧 API，这条测试会先断。

补齐内容（`scripts/verify-extensions-startup.js` 里的被测入口）：

```js
const readExts = (label, ses) => {
  if (!ses.extensions || typeof ses.extensions.getAllExtensions !== 'function') {
    throw new Error('当前内核没有 session.extensions.getAllExtensions（' + label + '），新命名空间缺失');
  }
  return ses.extensions.getAllExtensions();
};
```

两处读取分别改成 `readExts('persist:nyx-normal', …)` / `readExts('nyx-private', …)`；
**缺新 API 就抛错**，不静默退回弃用写法。

另加一条静态守卫（项数 10 → **11**）：写入被测入口后读回源码，断言
`entrySource.includes('.extensions.getAllExtensions(')` 且
`!/fromPartition\([^)]*\)\.getAllExtensions\(/.test(entrySource)`，
项名「被测入口用 session.extensions 新命名空间（不碰已弃用的 session.getAllExtensions）」。

顺带修掉一个会让脚本**挂住且零输出**的坑：`electronBin = require('electron')` 在
"用 electron.exe 直接跑本脚本"时返回的是 API 对象，`spawnSync` 报
`The "file" argument must be of type string. Received an instance of Object` 然后卡死；
改成 `typeof mod === 'string' ? mod : process.execPath` + 存在性检查 + 明确报错。

实测：`共 11 项，失败 0 项`，stderr 里不再出现 `session.getAllExtensions` 的弃用告警
（`src/core/extensions.js` 的主进程侧是否还有旧调用，另见 T1-3 的边界说明）。
