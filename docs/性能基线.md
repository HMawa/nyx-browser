# Nyx 性能基线（清单 C2）

> 一句人话：**体积是硬盘上的字节数，占用是运行起来占的内存**，两件事分开记，别混着说。
> 这份文件只记"量出来的数"，不记"感觉快了"。

## 怎么量

```powershell
node scripts/measure-baseline.js                 # 量开发运行（node_modules 里的 electron）
node scripts/measure-baseline.js --exe="D:\Nyx-src\dist\win-unpacked\Nyx.exe"   # 量打包后
node scripts/measure-baseline.js --json          # 一行 JSON，给脚本用
```

测量本身的三条纪律：

1. **隔离**：`NYX_USER_DATA` 指到 `%TEMP%\nyx-baseline-<时间戳>`，跑完删掉，不动真实用户数据。
2. **不联网**：5 个标签页来自本进程起的本地 HTTP 服务，避免"网慢了所以启动慢"的误判。
3. **只算自己**：进程树按父链（`ParentProcessId`）枚举，不会把别的 Electron 应用算进来。

## 基线（2026-11-15，开发运行，Electron 45.3.2 / Chromium 156.0.8078.100）

| 指标 | 实测 | 说明 |
| --- | --- | --- |
| 冷启动 → 主窗口可连 CDP | **386 ms** | 不含安装、不含首次生成配置 |
| 冷启动 → preload 就绪（`window.nyx` 可用） | **448 ms** | 用户真正能点的那一刻 |
| 1 个标签 | **5 个进程 / 657.4 MB** | 标签 + 图形 + 工具 + 主进程 + GPU 辅助 |
| 5 个标签 | **9 个进程 / 1083.9 MB** | 每多一个标签约 +107 MB |
| 装包体积 | **127,233,480 字节（121.3 MB）** | `dist\Nyx-Setup-1.17.8.exe` |
| 解包目录体积 | **408,640,000 字节（389.7 MB）** | `dist\win-unpacked`，安装后落盘量级 |

同一台机器、同一时刻，换 `--exe=dist\win-unpacked\Nyx.exe`（打包后、`app.asar` 参与）再量一次：

| 指标 | 实测 | 与开发运行比 |
| --- | --- | --- |
| 冷启动 → 主窗口可连 CDP | **380 ms** | 基本一样（热缓存下 asar 不是瓶颈） |
| 冷启动 → preload 就绪 | **449 ms** | 基本一样 |
| 1 个标签 | **5 个进程 / 663.8 MB** | +6.4 MB |
| 5 个标签 | **9 个进程 / 1086.7 MB** | +2.8 MB |

## 这些数字怎么读（诚实边界）

- **工作集合（Working Set）会重复计算共享页**：Chromium 的若干进程共享同一份只读代码页，把每个进程的
  Working Set 直接相加，加起来比真实物理内存占用偏大。要看"真实占用"请用任务管理器「内存」列或
  RAMMap 的 Private Bytes；这里记 Working Set 是为了**同一把尺子前后比较**。
- **1 个标签 657 MB 里有一大块是 GPU 进程**：Nyx 默认走 `low-power` 启动策略（`GPU_ADAPTER` 诊断里能看到），
  独显机器上图形进程会吃掉几百 MB。这是 Chromium 的行为，不是 Nyx 自己的分配。
- **冷启动 386 ms 是开发运行**：从源码目录跑、`app.asar` 没参与、磁盘缓存是热的。打包后实测 380 ms，
  说明热缓存下 asar 不是瓶颈；但**安装版的第一次启动**（解包 + 首帧管线）会明显更慢，要量就在装完后立刻量一次。
- **体积 ≠ 占用**：安装包 121.3 MB、解包 389.7 MB，都是硬盘数字；它们跟"打开 5 个标签占 1 GB 内存"没有直接关系。
