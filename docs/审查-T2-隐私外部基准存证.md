---

## 1. 现象（动手前是什么样）

隐私自检能告诉你「这一次 16 项分别什么结论」，但**没有参照物**：

- 换了一台机器、换了一次内核版本、换了一次系统缩放，自检结论变了，你看不出是"我改了什么"还是"环境变了"。
- 想把这个结论交给运维/审计留档，只能整段截图，人眼比对。

T2 要的是：**能生成一份只含结论的基准文件、入库、以后每次自检自动和它比**，而且这份文件本身**不能反推出这台机器的真实指纹**。

---

## 2. 取证（改之前先确认现状）

| 位置 | 事实 |
| --- | --- |
| `src/core/privacy-check.js` | `buildReport(rows, meta, options)` 里 `redact` 默认 true、真实值写「—（已隐藏）」；但**没有"把结论存成文件"的能力** |
| `scripts/privacy-audit.js` | `main()` 直接 process.exit，没有导出；切模式失败读 `switchRes.error`，而 IPC 实际返回的是 `message` |

| `docs/privacy-audit/*.md` | 只有 markdown 报告，没有可机读的基准 |

## 3. 改了什么

### 3.1 纯逻辑（新增 `src/core/privacy-baseline.js`，零依赖）

| 函数 | 作用 |
| --- | --- |
| `buildBaseline(rows, meta, options)` | 出 `{kind, at, version, electron, chromium, identity, kernelRunning, counts, rows}`，每行只留 `{id, level, title, reason}`，`reason` 过一遍 `scrubText` + `scrubSecrets` |
| `parseBaseline(text)` | 入库守卫：`kind` 不对、缺 `rows`、行里出现 `observed`/`truth` → `{ok:false, error}` |
| `compareBaseline(currentRows, baseline)` | 只比 `level`，出 `{comparable, lines, changed[], missing[], added[], sameCount}` |
| `scrubText(text)` / `scrubSecrets(text, secrets)` | 打掉 IPv4 / IPv6 / 24 位以上十六进制 / 已知真值 |
| `describeBaseline(baseline)` | 中文一行：「2026-11-23 生成（1.19.2）：16 项｜测不到 4 / 已伪装 3 / 正常 9」 |
| `baselineFileName(at)` / `keepLatestNames(names, limit)` | 日期命名 + 轮换（`MAX_BASELINES = 12`） |

关键取舍：**只比结论，不比观察值**。比观察值等于把真实指纹抄进比对结果里，而这份结果会显示在界面上、会被人复制出去。

### 3.2 生成脚本（新增 `scripts/privacy-baseline.js`）

`node scripts/privacy-baseline.js` 写 `docs/privacy-baseline/<日期>.json`，并**同时**同步一份到 `<userData>/privacy-baseline/`——打包产物只含 `src/**/*`，不含 `docs/`，设置页要能读到就得有一份在用户数据里。

四个开关：`--dry-run`（只打印不写）、`--raw`（额外把含真实值的原始件写到 `temp/privacy-baseline/`，不入库）、`--check`（校验最新一份干净：无 IPv4、无 24 位以上十六进制、无真实 UA 串、无 observed/truth）、`--keep N`（轮换）。

### 3.3 界面与主进程

- `src/main.js` 新增 IPC `nyx:privacy:baseline`：同时扫 `<userData>/privacy-baseline` 与 `app.getAppPath()/docs/privacy-baseline`，按文件名倒序取最新，`parseBaseline` 守卫，**只读不写**。
- `src/preload.js` 加 `privacyBaseline(payload)`。
- `src/renderer/settings.html` 在自检表后插入「对照基准」块（`#privacy-baseline-head` 用 `role=status aria-live=polite`，差异列表 `#privacy-baseline-diff`）。
- `src/renderer/settings.js` 新增 `loadPrivacyBaseline(rows)`：无接口 / 读失败 / `ok:false` / 没有基准，四种都有中文人话；比不了（`comparable === false`）时把原因顶到标题行。

### 3.4 顺带修的两处真问题

1. `scripts/privacy-audit.js` 切模式失败文案读 `.error`（不存在）→ 改 `switchRes.message || switchRes.error || switchRes.reason`。原来一直显示"未知原因"。
2. 新增 `readApiPort(userData, fallback)` 轮询 `api-port.txt`（剥 BOM）。端口被占时 `startHttpApi` 会换端口，只看 `NYX_API_PORT` 会等到超时，表现成"本地接口没就绪"——**这是个会让人误判产品坏了的假失败**。

## 4. 验证（数字）

```
node scripts\verify-privacy-surface.js      → 84/84（改前 70，新增 14 项）
node scripts\privacy-baseline.js            → exit 0，写 16 项基准（2,256 ms）
node scripts\privacy-baseline.js --check    → ✔ 最新基准干净（16 项，2349 字节）
npm run verify                              → 53 个脚本 / 53 通过 / 0 失败 / 0 跳过 / 1220 项 / 560 秒
git grep -E "172\.|192\.168\.|10\.0\." -- docs/  → 无命中
```

新增的 14 项断言里，这几条是真正守住口径的：

| 断言 | 守的是什么 |
| --- | --- |
| 基准里没有可反推本机的真值（只扫 `JSON.stringify(rows)`） | 入库件不能带真实指纹（扫整份会假红——`meta.chromium` 本来就是构建版本） |
| 理由里的值被替换成 `—（已隐藏）` | 脱敏发生在生成阶段，不是展示阶段 |
| 带 `observed` 的文件被拒 / `kind` 不对被拒 | 别人手改基准文件也塞不进来真值 |
| 变了要说「A1 已伪装 → 泄漏」 | 比对结果必须说清"从什么变成什么"，不是只报"不一样" |
| 生成脚本不含 `fetch(` / `http(s)://` | 这条链路不许联网（产品红线：不做内置 AI、不外传数据） |
| 主进程 handler 同时覆盖两个目录且不写盘 | 打包版没有 `docs/`，读不到就会静默空着 |

## 5. 这条能证明什么 / 不能证明什么

**能证明**：基准文件只含结论、入库前有守卫、比对是逐项且说清变化的、生成链路不联网。

**不能证明**（写进文档，别当已解决）：

- **不证明这台机器现在没泄漏**。基准记录的是"当时测出来是什么"，如果当时就已经错了，基准会把错误结论固化下来。
- **DNS 永远测不到**（浏览器看不见系统解析），所以 C2/C3 恒为「测不到」，基准里也一样。
- 基准只比 `level`，**同一档内变差（比如都判"已伪装"，但伪装得像不像）看不出**。
- 没有分数、没有及格线——刻意不做，避免"88 分所以安全"这种自欺。

## 7. 踩过的两个坑（给后来人）

1. `edit` 的 `old_string` 若以换行结尾，会把相邻空行/注释行一起吞掉并挤成一行。本轮在 `src/main.js` 与 `src/renderer/settings.js` 各踩一次，靠读回文件才发现。
2. `scrubText` 的 IPv6 正则原来只认 `(?:[0-9a-f]{1,4}:){2,7}`，`2001:db8::1` 这种缩写洗不掉（断言先红才暴露），改成 `/\b[0-9a-f]{0,4}(?::[0-9a-f]{0,4}){2,7}\b/gi`；顺手确认 `12:30` 这种单个冒号的时间不会被误伤。
