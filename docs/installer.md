# 安装与卸载

Nyx 在 Windows 上以 NSIS 安装包分发，文件名形如 `Nyx-Setup-<版本>.exe`。本文说明安装前的环境检查、四种安装模式、自定义目录、依赖与推荐下载、安装报告、完整性校验、完全卸载、静默安装开关与常见故障排查。

> 本文用 `<安装目录>` 表示安装向导中实际选择的目录（默认位于当前用户的程序目录，安装完成后也可在系统「应用与功能」里查看），用 `%APPDATA%\Nyx` 表示当前用户的个人数据目录（书签、历史、设置等）。

---

## 1. 安装前的环境检查

安装向导在选择目录之后有一页「环境检查」，自动检测并给出结论。检查项与判定如下：

| 检查项 | 要求 | 不满足时的结果 |
| --- | --- | --- |
| 系统版本 | Windows 10 1809（构建号 17763）及以上 | 低于 17763 直接**阻断**安装 |
| 系统版本（推荐） | Windows 10 2004（构建号 19041）及以上 | 17763–19040 之间给出**警告**，仍可继续 |
| 系统架构 | x64 | ARM64 等非 x64 架构给出**警告**（内核二进制只有 windows-amd64 版本） |
| 安装目录 | `<安装目录>` 可创建、可写入 | 不可写时**阻断**（通常是权限或安全软件拦截） |
| 磁盘空间 | 目标盘剩余 ≥ 1.5 GB | 不足 1.5 GB **阻断**；1.5–2.5 GB 之间给出**警告** |
| 运行库依赖 | Electron 自带运行库，无需额外安装 .NET / VC++ | 无需处理；仅提示内核随包分发 |
| 旧版本 | 读取本机已登记的 Nyx 版本与安装位置 | 用于判定全新 / 升级 / 修复 / 降级，见下节 |

检查结果会一并写入安装报告。**阻断项**只能取消安装或处理后重试；**警告项**可以继续，但建议按提示处理（例如腾出磁盘空间、确认系统版本）。

---

## 2. 全新安装 / 升级安装 / 修复安装 / 降级

安装器读取当前用户注册表里的 Nyx 安装登记信息（安装位置与版本号），并核对 `<安装目录>\Nyx.exe` 是否存在，据此判定安装模式：

| 本机情况 | 判定模式 | 行为 |
| --- | --- | --- |
| 没有可用的旧安装登记，或登记位置里找不到 `Nyx.exe` | **全新安装** | 复制全部程序文件，创建快捷方式与卸载信息 |
| 已安装旧版本，且旧版本号 **低于** 当前安装包版本 | **升级安装** | 覆盖程序文件；**保留** `%APPDATA%\Nyx` 里的个人数据 |
| 已安装同版本 | **修复安装** | 重新覆盖程序文件，用于修复文件缺失或损坏；个人数据不变 |
| 已安装**更高**版本 | **降级安装** | 先给出降级**警告**，由用户决定是否继续 |

要点：

- 四种模式都**不会**主动删除 `%APPDATA%\Nyx`；覆盖安装、升级、修复都保留个人数据。
- 覆盖安装会替换 `<安装目录>` 内的程序文件，但不会动同目录下用户自己放的其他文件（仍建议安装前关闭 Nyx）。
- 安装模式会写进安装报告，静默安装时可用于核对是否按预期执行。

---

## 3. 自定义安装目录

- 安装向导的「选择安装目录」页可修改 `<安装目录>`；安装器会检查该目录是否可创建、可写。
- 同版本/新版本的覆盖安装会复用已登记的安装位置；更换目录相当于安装到新位置，旧目录需要手动删除。
- 安装目录会被记录到注册表，卸载与快捷方式都依赖它，**不要手工移动**安装目录（移动后卸载器会找不到自身）。
- 个人数据始终存放在 `%APPDATA%\Nyx`，与安装目录无关，因此重装到其他盘不会丢数据。

## 4. 依赖与推荐下载

| 依赖 | 说明 |
| --- | --- |
| mihomo 内核 | 随安装包分发：`<安装目录>\resources\vendor\mihomo\mihomo.exe`，版本见同目录 `VERSION.txt`；无需单独安装 |
| geo 规则数据 | 随包分发：`<安装目录>\resources\vendor\geo\`（`geoip.metadb`、`geosite.dat`） |
| Electron 运行库 | 已随程序自带，**不需要**安装 .NET Framework 或 VC++ 运行库 |
| 系统组件 | 无需额外组件；系统版本要求见第 1 节 |

如需自行更新内核或规则数据，可从上游官方发布页下载对应文件后替换（替换后完整性校验会报告不一致，属于预期）：

- mihomo 发布页：<https://github.com/MetaCubeX/mihomo/releases>
- 规则数据发布页：<https://github.com/MetaCubeX/meta-rules-dat/releases>

升级内核属于高级操作：版本不匹配可能导致程序无法启动，出问题请重新安装覆盖。

## 5. 安装报告

安装器在完成文件复制与完整性自检后，会把本次安装的关键信息写到：

```
%APPDATA%\Nyx\install-report.txt
```

- 编码为 UTF-16LE（带 BOM），Windows 记事本可直接打开；用其他编辑器打开时请选择 UTF-16 LE。
- 每次安装/覆盖安装都会重写该文件，只保留最近一次记录。

字段说明：

| 字段 | 含义 |
| --- | --- |
| 时间 | 本次安装完成时间 |
| 安装器版本 | 安装包版本号 |
| 安装目录 | 本次安装的 `<安装目录>` |
| 安装模式 | 全新安装 / 升级安装 / 修复安装 / 降级安装 |
| 系统与构建号 | 系统名称与构建号 |
| 架构 | x64 等 |
| 目标盘剩余 | 安装时目标盘剩余空间 |
| 旧版本 | 本机检测到的旧版本（没有则为空） |
| 内核版本 | 随包内核版本（来自 `VERSION.txt`） |
| 完整性检测结果 | 安装时自动校验的结论（通过 / 失败） |
| 数据目录 | 个人数据位置，即 `%APPDATA%\Nyx` |
| 卸载命令 | 静默卸载命令，形如 `"<安装目录>\Uninstall Nyx.exe" /S` |
| 安装器路径 | 本次运行的安装包路径 |

示例（字段值为演示用，`<>` 为占位）：

```
时间：2026-01-01 12:00:00
安装器版本：<版本号>
安装目录：<安装目录>
安装模式：全新安装
系统：Windows 10 专业版（构建号 19045）
架构：x64
目标盘剩余：<剩余空间>
旧版本：（无）
内核版本：<内核版本>
完整性检测结果：通过
数据目录：%APPDATA%\Nyx
卸载命令："<安装目录>\Uninstall Nyx.exe" /S
安装器路径：<安装包路径>
```

安装时的完整性自检结果还会单独写到 `%APPDATA%\Nyx\integrity-check.txt`。自检失败**只警告、不阻断**安装：若报告里显示失败，请按第 6 节手动复查，必要时重新安装。

## 6. 完整性校验

安装包内附带一份 SHA-256 清单 `resources\integrity.json`，覆盖 `app.asar`、`vendor/**`、`licenses/**`、`LICENSE`、`THIRD-PARTY-NOTICES.md`。校验分三层：

### 6.1 安装时自动校验

安装器复制完文件后会静默执行一次程序自检（不弹窗口），结果写入安装报告与 `%APPDATA%\Nyx\integrity-check.txt`。失败仅警告，安装继续。

### 6.2 手动校验已安装程序

```powershell
"<安装目录>\Nyx.exe" --verify-integrity
"<安装目录>\Nyx.exe" --verify-integrity --report=<报告路径>
```

- 不创建窗口，只做校验后退出。
- 退出码 `0` 表示全部一致；`1` 表示存在缺失、大小不符或哈希不一致。
- 加 `--report=` 可把逐文件明细写到指定文件，便于排查。
- 修改或替换过内核/规则文件后校验会失败，这是预期行为；想恢复一致状态请重新安装。

### 6.3 开发与打包环节校验

在源码仓库中（解包版 `dist\win-unpacked` 已生成）可执行：

```powershell
node scripts/verify-integrity.js [产物目录]
# 或（package.json 里配置的快捷方式）
npm run verify:integrity
```

- 产物目录可省略（默认 `dist\win-unpacked`），也可直接指向含 `integrity.json` 的 `resources` 目录。
- 用途是在改打包配置后确认 `resources\integrity.json` 与随包文件一致；`npm run dist` 打包时会自动生成该清单。
- 脚本只读产物目录，不修改任何文件；缺失文件与哈希不符会逐条打印并与 `--verify-integrity` 使用同一份清单。

### 6.4 校验失败怎么处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 找不到 `resources\integrity.json` | 安装包/解包产物不完整，或用了旧版构建 | 重新安装或重新打包 |
| 某个 vendor 文件哈希不一致 | 手动替换过内核或规则数据 | 重新安装，或从上游重新下载官方文件 |
| `app.asar` 不一致 | 程序文件被改动、被安全软件修改 | 重新安装 |
| 退出码 1 但报告无明细 | 报告路径不可写 | 换一个可写路径再执行 `--report=` |

## 7. 完全卸载

### 7.1 正常卸载

在「设置 → 应用 → 已安装的应用」中卸载「Nyx 隐私浏览器」，或运行 `<安装目录>\Uninstall Nyx.exe`。

卸载过程会：

- 关闭正在运行的 Nyx 进程；
- 删除桌面与开始菜单快捷方式、卸载登记信息；
- 删除 `<安装目录>` 与安装目录下的 `updates` 缓存；
- 清理 `%LOCALAPPDATA%\Nyx` 缓存目录与 `%TEMP%` 下的临时残留；
- 询问是否**同时删除个人数据**（默认「否」）：选「否」保留 `%APPDATA%\Nyx`，下次安装可继续使用原书签、历史与设置；选「是」则一并删除。

### 7.2 完全卸载（连个人数据一起删）

交互模式在卸载时会询问；静默模式必须显式加开关：

```powershell
"<安装目录>\Uninstall Nyx.exe" /S /DELETEAPPDATA
```

### 7.3 卸载残留

- 只想清空个人数据但保留程序：手动删除 `%APPDATA%\Nyx`（会丢失书签、历史、设置，务必先备份）。
- 卸载后仍有快捷方式：刷新桌面或重新登录；也被删除的旧快捷方式不会自动回来。
- 注册表里若仍有 Nyx 残留项，通常重新安装一次再卸载即可清掉；不要手工删除不认识注册表项。

## 8. 静默安装与静默卸载

适合批量部署或自动化测试。

| 命令 | 作用 |
| --- | --- |
| `Nyx-Setup-<版本>.exe /S` | 静默安装到默认目录，不弹任何界面 |
| `Nyx-Setup-<版本>.exe /S /D=<安装目录>` | 静默安装到指定目录 |
| `"<安装目录>\Uninstall Nyx.exe" /S` | 静默卸载，**保留**个人数据 |
| `"<安装目录>\Uninstall Nyx.exe" /S /DELETEAPPDATA` | 静默卸载，**删除**个人数据 |

注意：

- `/D=` 必须是**最后一个参数**，且路径**不能加引号**；路径里尽量不含空格（NSIS 静默模式对空格路径支持有限，推荐用不含空格的目录）。
- 静默安装不会自动启动 Nyx；如需安装完立即启动，可加安装器自带的 `--force-run` 开关。
- 静默模式不弹窗、不代表没有返回值：退出码 `0` 表示成功，非 `0` 表示失败；失败原因可结合安装报告排查。
- 覆盖安装（升级/修复）默认保留 `%APPDATA%\Nyx`，不要在部署脚本里额外删除该目录。

仓库内提供了安装器端到端回归脚本（需要已构建好的安装包，且会真实安装/卸载）：

```powershell
node scripts/test-installer-e2e.js --installer=<安装包绝对路径>
```

脚本会依次验证静默全新安装、覆盖修复、保留数据卸载、`/DELETEAPPDATA` 完全卸载，并在开始前备份、结束后还原本机的用户数据、注册表登记与快捷方式。

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 安装时弹出 UAC / 管理员确认 | 安装到受保护目录，或系统策略要求提权 | 同意提权；只想装给当前用户时改选用户目录 |
| 「无法写入安装目录」 | 权限不足、目录被占用、安全软件拦截 | 换目录或授予权限；关闭占用该目录的程序后重试 |
| 提示文件被占用 / 卸载失败 | Nyx 仍在运行，或安装目录被资源管理器打开 | 退出 Nyx、关闭打开该目录的窗口后重试 |
| 环境检查页显示阻断 | 系统版本过低、磁盘空间不足、目录不可写 | 按页面提示升级系统 / 清理磁盘 / 换目录 |
| 完整性校验失败 | 文件被修改、替换过内核、安全软件改动文件 | 重新安装；或用 `--verify-integrity --report=` 看明细 |
| 安装报告或 `integrity-check.txt` 缺失 | 个人数据目录不可写、`%APPDATA%` 被重定向 | 检查目录权限；确认当前用户对 `%APPDATA%` 可写 |
| 卸载后仍有 Nyx 进程 | 卸载器结束进程失败 | 手动结束后重新卸载 |
| 静默安装返回非 0 | 参数错误（如 `/D` 不是最后一个参数、路径带引号）、空间不足、文件被占用 | 按上表逐项排查，并查看安装报告 |
| 杀毒软件/SmartScreen 提示 | 安装包或内核未做代码签名 | 确认下载来源可信后允许运行；内核完整性由 `resources\integrity.json` 校验 |

若问题仍无法定位，请保留 `%APPDATA%\Nyx\install-report.txt` 与 `%APPDATA%\Nyx\integrity-check.txt`，它们记录了安装模式、系统信息与校验结论。
