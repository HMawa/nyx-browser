## 二、逐项说明

### 2.1 统一检查更新

- 新 IPC `nyx:update:check-all`：应用侧调用现有 `Updater.check()`，扩展侧读更新源 `extensions.json` 并与已装版本比对；
- 设置 → 关于与更新里的「检查更新」按钮改为调这个入口，状态栏一次给出两句结论：`应用已是最新（1.12.0）；扩展有 1 个更新（到「扩展插件」→「扩展更新」卡片点「全部更新」）`；
- 兜底：老 preload 没有该 API 时退回只查应用，不会崩。

### 2.2 地址栏置顶管理

- 设置 →「外观」新增卡片：列出置顶项（`#1`…），支持**原生 HTML5 拖动**排序、`↑ ↓` 按钮兜底、`取消置顶`；
- 新 IPC `nyx:as:pinned-reorder { urls }`：按给定顺序重排，未列出的保持在后；上限 5 条不变；
- 顺序会立即影响地址栏建议的排序（置顶项始终在最前）。

### 2.3 抓包多请求瀑布

- 详情抽屉新增第 4 个分区「瀑布」：取当前标签 `seq` 最大的最近 30 条请求，画在同一时间轴上；
- 原点 = 最早 `at`；条起点 = `at − 原点`、长度 = `duration`；有 `timing` 拆「等待 / 下载」两段；
- 失败（`failed` 或 ≥400）用 `--danger-*`、进行中半透明 + 「…」、超轴截断标 `»`；顶部 5 条刻度（ms↔s 自动）；
- 点击某行 → 切回「概览与头」并打开该请求详情；空态「暂无可用于瀑布的请求」。时间轴跨度上限 60s（超出按比例压缩并标 `»`）。

### 2.4 `--clean-updates --out`

`--clean-updates --json --out <file>`：文件内容与 stdout 完全一致（UTF-8 无 BOM + 末尾换行），目录自动递归创建；`--out` 不带 `--clean-updates` 直接报错；写入失败 exit 1。实测文件与 stdout 均 1024 字节且内容相等。

## 五、已知边界

1. 安装版仍为 1.2.9；升级走应用内「检查更新」（现在会同时告诉你扩展是否有更新）。
2. 置顶上限 5 条；拖动排序为原生 HTML5 drag，触屏设备建议用 ↑↓ 按钮。
3. 瀑布时间轴跨度上限 60s，超长请求会被压缩并标 `»`；只有总耗时没有分段时显示单色条。
4. `--out` 只导出报告、不参与清理决策；文件原地覆盖不备份。
