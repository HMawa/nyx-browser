# Nyx 1.18.2 脱敏补正

> 一句话：**`v1.18.2` 这个 tag 指向的那棵树里还有一处本机构建环境的真值残留；`main` 已经干净。
> 本文件记录这件事、处置方式，以及为什么没有改写历史。**

日期：2026-11-18
相关：`docs/Nyx-1.18.2-发版记录.md` §8.3（B1 的选择）、`docs/实测修复台账.md`

---

## 1. 残留是什么

`git show v1.18.2:docs/实测修复台账.md` 里，1.18.2 批次那张表的「应用页无 WebRTC 策略」一行，
改法说明中写着一个**内网地址实例**（`172.24.64.1`）——它是这台构建机在做自检时
`RTCPeerConnection` 真实吐出来的本机地址。

`main` 上的同一处已经改成不带具体值的描述（`git grep -F "172.24" -- docs` = 0 命中）。

## 2. 为什么没有把 tag 挪过去

- **红线 8：禁止改写 git 历史 / force push。** 移动 tag 属于改写引用，即使只换指向。
- 更关键：**挪 tag 也删不掉 blob。** 那条内容已经在 `v1.18.2` 之前的提交里（`dfc311d` 一带），
  移动引用只会让「tag 里还有」变成「历史里还有」，读起来更糟——标签是人会去翻的入口，
  把入口擦干净而把内容留在历史深处，比老实承认更不诚实。
- 删文件同样无效：`git rm` 只影响之后，旧 blob 仍在对象库里。

## 3. 处置

1. **`main` 上补正**（`ef5f876` 及后续提交）：把具体值换成形状描述，并逐 token 扫过一遍
   `docs/`（真实 UA 串、两位数核数、四位数分辨率、Asia 时区、小写语言地区标签、内网段、
   屏幕缩放），**0 命中**。
2. **新增 tag `v1.18.2-post`** 指向补正后的 `main`。用途很明确：
   要看「脱敏之后的样子」，checkout 这个 tag；要复现 1.18.2 的产物，用 `v1.18.2`（安装包字节不变）。
3. **`v1.18.2` 保持原样**，本文件就是它的说明。

## 4. 克隆者需要知道的三件事

1. `v1.18.2` 树里那条内网地址是本机环境信息，**不涉及任何用户数据**——Nyx 没有上传通道，
   自检只在本机跑、结果只写本地文件。
2. 想知道「现在的口径长什么样」，看 `v1.18.2-post`（或更新的 tag）与 `main`。
3. 1.18.2 之后所有自检存证一律**默认脱敏**：真实值列写 `—（已隐藏）`，
   原始 JSON 只落 `temp/privacy-audit/` 且不入库；生成时加 `--raw` 才出原始版。

## 5. 这件事留下的规矩

- **存证类文档默认脱敏**，`docs/` 里不许出现可直接指认构建机的值（UA 串、核数、分辨率、
  时区、缩放、内网地址）。
- 提交存证前跑一次逐 token 扫描（形状清单见上），**扫不到才算干净**。
- 打 tag 前要 `git show <tag>:<文件>` 复核，而不是只看工作区——tag 记的是那一刻的树。
