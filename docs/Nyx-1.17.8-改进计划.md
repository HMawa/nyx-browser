## 1. 首批（进 v1.17.8）三条：A1 → A2 → A3

### A1 设置页：所有选项改成「铺开 / 收回」两态

**做法（不改滚动容器，只在卡片上加折叠语义）**

1. `src/renderer/settings.html`：40 个 `section.info-card` 保持结构不动，由 `settings.js` 在启动时**统一增强**成折叠单元（不手改 40 处 HTML，避免大改面）。
   - 每张卡片的 `<h3>` 外面包一层 `<button class="card-fold" aria-expanded="true" aria-controls="…">`，右侧加一个「当前值」槽位 `<span class="card-value">`；
   - 分区标题栏右侧加全局按钮「全部铺开 / 全部收回」（每区一个，作用于本区）。
2. **当前值怎么来**（这条是"收起不等于看不见"的关键）：自动推导，按优先级取卡片里第一个控件——
   `input[type=checkbox]` → 「开 / 关」；`select` → 选中项文本；`input[type=text/number]` → 值（超过 24 字截断）；都没有 → 取卡片里第一条 `.hint` 的首句。推导写成一个纯函数 `describeCardValue(card)`，好断言。
3. 状态持久化：`ui-store` 新增 `settingsFolded: {}`（key = 卡片 `data-fold-id`，值为 `1` 表示收起）。**跨分区、重启后仍记住**。
4. 收起动画：`max-height` + `opacity`，120–180ms，`@media (prefers-reduced-motion: reduce)` 时直接切换。
5. 默认态（**待确认**）：常用区（外观、网络与代理）默认铺开，其余默认收回。

**验收断言**（写进 `scripts/verify-ui-polish.js`，+4 项）
- 任一卡片可单独铺开/收回，`aria-expanded` 跟着变；
- 全局按钮一次全开/全收，且 `ui-preferences.json` 里 `settingsFolded` 被写；
- 收起态下每张已收起的卡片 `card-value` **非空**（"看不见当前值"就是不合格）；
- 刷新页面后展开状态与刷新前一致。

### A2 页面摘要：展开后不再被压住

**根因**：摘要面板 `z-index: 40` 低于工具箱 `900` 与提示 `1000`，且两者都占右侧。

**做法**
1. 摘要面板层级提到 **950**（高于工具箱、低于提示 toast）；
2. 工具箱打开且摘要也开着时，摘要面板**左移避让**：`right: calc(14px + var(--toolbox-width, 0px))`，由 `renderer.js` 在工具箱开合时写 CSS 变量（不硬编码宽度，沿用工具箱现有宽度档位）；
3. 展开内容自动滚入可视区：`scrollIntoView({ block: 'nearest' })`，只在"内容底边超出面板可视区"时触发。

**验收断言**（+2 项）：最窄窗口（1024×700）下点开摘要，末条可见（`getBoundingClientRect().bottom <= panel.bottom`）；工具箱同时打开时两者**不重叠**（矩形不相交）。

### A3 进程面板：写清每条进程在干什么

**做法**
1. 新增 `src/core/process-panel.js`（纯逻辑、零 Electron）：
   - `describeProcess(metric, tabInfo)` → `{ friendly, type, label }`：`friendly` 按进程类型给中文（浏览器主进程 / GPU 进程 / 网络服务 / 渲染进程 / 工具进程），`label` 取「标签标题 · 域名」，没有标签时如实写「无对应标签（可能是扩展或预渲染进程）」；
   - `buildProcessRows(metrics, tabs)` → 排序后的行数组（主进程在最上，渲染进程按标签顺序）；
   - `summarizeProcesses(rows)` → 「N 个进程，合计 X MB」。
2. `src/main.js`：`app.getAppMetrics()` 取数据；**自己维护 `wcId → { tabId, title, url }` 映射**（在 `createTab` / `did-navigate` / `page-title-updated` 里更新，在 `close` / `render-process-gone` 里**删除**——清单点名的泄漏点）；IPC `nyx:proc:list`。
3. 界面：放**设置 → 诊断**分区（清单要求"诊断类不上首装引导"），表格列「进程 / 类型 / 对应页面 / 内存 / CPU」，10 秒刷新一次，离开分区即停。

**验收断言**（新脚本 `scripts/verify-process-panel.js`，~8 项 + 界面 2 项）：纯逻辑的友好名/标签归属/无标签兜底/合计；接线（IPC、`delete` 清理、诊断分区、刷新定时器在离开分区时被清）。

## 3. 回清单 §5 的五个问题

1. **Agent 化到哪一步、有没有能握手的端点？**
   A–G 七项全部完成。端点两条：**MCP（stdio，`src/mcp/server.js`，转发到本地 HTTP）** 与 **HTTP 接口（仅回环 + `x-nyx-token` 鉴权）**；9 个动作（`navigate` / `readPage` / `screenshot` / `click` / `type` / `executeJS` / `extractText` / `state` / `settings`）。双模切换、`restartRequired`、常驻「审计不完整」都在。**所以 D1 可以写实话术，不用出雏形。**
2. **现在的包大小 / 冷启动 / 5 标签 RSS？**
   包大小确定：**127,225,416 字节（121.3 MB）**。冷启动与 RSS 我不在这份计划里凭记忆填数——C2 第一步就是量，方法：隔离 `NYX_USER_DATA` 启动、CDP `Page.loadEventFired` 到首帧可交互、`app.getAppMetrics()` 求和；两组数字会和改后一起给。
3. **设置页展示不全，是一个根因还是多个？**
   **不是滚动问题**：每区已有独立滚动。真根因是**没有折叠**——40 张卡全摊开，扫读成本高、找一项要滚很久。所以 A1 是"加折叠语义"，一处设计、全站生效。
4. **抓包是"不跟随切页"还是"要重启抓包"？期望哪种？**
   代码里已有跟随开关（`#net-follow`）与换标签刷新，但只在开关勾选时生效，且记录/监听按 `webContents.id` 分离。清单要求"两种都要"，因此 A4 改成**显式两模式**：跟随（默认）/ 独立（按标签留存，可回看）；两种模式切换后旧记录不串台；**面板关闭即释放监听**。
5. **哪些主界面按钮从不用？**
   没有真数据我不猜。B1 按清单做成"默认精简 + 用户自选"，并用默认精简后的实际使用情况回收数据（按钮点击计数进诊断日志，只统计次数、不记内容）。
