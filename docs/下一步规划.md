# Nyx 下一步规划（2026-11-17）

> 这份文档回答三个问题：现在处在哪、接下来先做什么、什么不做。
> 进度的事实源仍是 `docs/实测修复台账.md` 与 `AGENTS.md`；本文件只排优先级，不重复逐项明细。

---

## 1. 现状盘点（2026-11-17 实测，不是估算）

| 项 | 实测值 |
| --- | --- |
| 已发布版本 | **1.17.10**（`%APPDATA%\Nyx\updates\latest.json` 指向它） |
| 工作区版本 | **1.17.19**，工作树干净 |
| 已构建未发布 | **1.17.11 – 1.17.19，共 9 个安装包**（11/16–11/17 两天内产出） |
| 发版文档 | `CHANGELOG.md` 与 `docs/Nyx-<版本>-发版记录.md` **只到 1.17.10** |
| 回归 | **47 个脚本 / 1066 项 / 607 秒**（本机，`verify-all` 自身会重试一次环境性失败） |
| 主进程 | `src/main.js` **9958 行**；`src/core/` **68 个模块** |
| 性能基线 | 冷启动 386/380 ms；1 标签 657.4 MB；5 标签 1083.9/1086.7 MB（`docs/性能基线.md`） |
| 安装包 | 1.17.19 = 127,295,424 字节，自签名有效（`CN=Nyx Self-Signed`） |

### 1.1 一个已确认的真故障：更新源指向不存在的包

- `latest.json` 写的是 `Nyx-Setup-1.17.10.exe`，但 `%APPDATA%\Nyx\updates` 里**只剩 `Nyx-Setup-1.17.10.blocks.json`，没有 exe**。
- 原因：`build/installer.nsh:687` 在每次安装/升级后执行 `Delete "$APPDATA\Nyx\updates\*.exe"`，把清单指向的那个包一并删了；`latest.json` 不会跟着前移。
- 后果：仍低于 1.17.10 的机器「检查更新」能查到新版本，点下载会得到 `更新源里没有找到升级包（已找：…）`（`src/core/updater.js:915`，失败可见，但升不上去）。
- 结论：**这不是一次性事故，而是每次发版后都会复发的设计缺陷**，必须连规则一起修，光补文件没用。

## 2. 核心判断

1. **最大的风险不是技术债，是发布欠账。** 隐私改造两批、模式切换 P0/P1、设置页重排、字号四档、导航预算、快捷键降级、停靠冻结——全部只存在于未发布的 9 个包里。堆得越久，1.17.10 → 最新代码的差集越大，真机出问题时定位成本越高。
2. **隐私做得实，但用户无法验证。** 指纹一致性、Worker 注入、WebGL/WebGPU/字体对齐都有实测证据，可这些只写在台账里。隐私浏览器的卖点必须能被外部复现，否则和「宣传口号」没有区别。
3. **质量地基开始出现隐忧。** 回归靠「内存紧张就重试一次」兜住；`main.js` 已接近一万行；两天内断言数从 1034 涨到 1066。按这个速度继续加功能，先坏的是回归的可信度。

## 4. H1 · 质量地基（发版后约一周，可与 H2 并行）

| 事项 | 为什么 | 验收 |
| --- | --- | --- |
| 回归分片 + 显式跳过 | 607 秒串行、低内存假失败靠重试掩盖；重试只能说明「不知道哪次是真的」 | 每个脚本仍独立可跑；跳过必须有原因打印；总时长下降 |

| 低内存场景下的启动探测 | 3 GB 可用内存时 Electron 启动偶发 CDP 超时，说明启动链路对内存敏感 | 有一条「可用内存 < 阈值时提示」的界面行为 |

## 5. H2 · 产品方向（三选一，推荐 A）

### A. 隐私可信度产品化（推荐）

把已经有实现的东西变成**用户可以自己验证**的资产：

- 一键自检页：指纹字段、WebRTC、DNS、时区/语言一致性、字体列表、Canvas 稳定性，一条条给「通过 / 不通过 / 不适用」；
- 每次发版自动跑 browserleaks / creepjs 的关键项并把结果存档，发版记录附「这一版改了哪些指纹面」；
- 补齐尚未覆盖的三处泄漏面：WebRTC 候选地址、DNS 出口、时区与语言的一致性。

为什么排第一：这是 Nyx 唯一的差异化，而且**最容易被外部审计检验**——现在被检验时只能靠人读台账。

### B. 日常可用性

内存（1 标签 657 MB、每标签约 +107 MB，值得单独查）、崩溃恢复、会话保存、快捷键与鼠标手势。
能扩大用户面，但不构成差异，且性能问题容易被误读成「浏览器很卡」。

### C. Agent 深化

已有 MCP、动作通道、站点三层授权、审计、导航预算、急停。下一步是任务级能力（结构化抽取配方、站点剧本、失败重试）。
产品红线禁止生成式功能，天花板明显；用户群最窄，建议最后做。

## 7. 不做清单（红线与已定结论，避免反复讨论）

- 不做内置生成式功能（产品红线）。
- 不做 asar 差分（只占整包约 8%，且拼出来的包没有 Authenticode 签名）。
- 不追求差分命中率：NSIS/LZMA 固实压缩下恒为 **0.00%**，`DIFF_MIN_HIT_RATE = 0.2` 的闸门必须留着。
- 不按进程名杀进程，不改 `vendor/`，不新增运行时依赖。
- 不用「放宽断言」的方式让回归变绿。
