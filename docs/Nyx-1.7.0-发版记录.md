## 二、逐项说明

### 2.1 「已在标签打开」提示

- 主进程在每次查询时扫一遍 `tabManager.snapshot()`，统计每个 URL 出现在几个标签里，给命中项附上 `openTabs` 与 `isActivePage`。
- 浮层展示：当前标签就是这个页面 → 徽标「当前页」；开了 1 个 → 「已打开」；开了多个 → 「×N」。徽标用中性色，比「书签」徽标更低调（它只是提示，不是来源）。
- 目的：用户想回到已开的页面时，一眼看出"已经开着"，不再重复开标签。

### 2.2 收藏到文件夹：自定义命名

- 浮层底部新增命名输入框（占位「新建文件夹名称（留空自动命名）」）：输入内容后回车，或用输入的名字点「新建文件夹并收藏…」，即可按自定义名称建文件夹并收藏；留空仍退回「新文件夹 <日期>」。
- 主进程清洗名字：去换行、去首尾空白、限长 64 字。
- **过程中修掉一个真 bug**：`addFolder({ parentId: 0 })` 会报「目标文件夹不存在」——`bookmarkStore.findById()` 把根节点排除在外；正解是**省略 parentId**（语义就是"建在根下"）。这个坑已写进 main.js 注释。

### 2.3 差分命中率：实测 0%，并加闸门（本轮最重要）

1.6.0 上线块级差分时，演练用的是"同一文件改 3 字节"，命中 98.68%。**真实两个发行版之间是多少？这轮量了**：

| 组（真实留档） | 256KB 块 | 512KB 块 | 1MB 块 |
|---|---|---|---|
| 1.4.0 → 1.6.0 | 0/453 = 0.00% | 0/227 = 0.00% | 0/114 = 0.00% |
| 1.5.0 → 1.6.0 | 0/453 = 0.00% | 0/227 = 0.00% | 0/114 = 0.00% |

原因：NSIS 安装包是 **LZMA 固实压缩流**，代码改一行整条流就重排，任何固定块都对不上。结论与处置：

- **差分对安装包切块几乎没有收益**，保留为"有则更好"的兜底，不当卖点；
- **新增命中率闸门**（`DIFF_MIN_HIT_RATE = 0.2`）：先只算"能命中多少块"、不下任何字节；命中率 < 20% 直接走整包。否则 0% 命中时仍会逐块 Range 拉全包（227 次往返），比整包更慢。
- 演练验证闸门：命中 0/8 块 → 日志「差分预计只命中 0/8 块（0.0%，低于 20%），改用整包下载」，**Range 请求 0 次**、差分返回 false 交给整包。
- 新增 `scripts/measure-delta.js`（可复跑）：`--base <旧.exe> --target <新.exe> [--sizes 262144,524288,1048576]`，输出命中率表格与结论。
- **app.asar 差分判断（不做）**：asar 未压缩、命中率会高，但只占整包 8.9MB / 7.9%，天花板≈8%，还要改分发形态——不值。

### 2.4 抓包列表站点图标

复用历史页签那套图标队列/首字母色块（没有写第二份实现）：每行在 URL 前加 16×16 图标；只给**可见行**排队（rAF 合并、每帧 ≤60、视口相交 ±120px 预取、面板未布局时退化为前 60 行），滚动懒加载；`onSiteIcons` 推送只替换对应行的图标槽，不整表重渲染（抓包列表几百行，重渲染会丢滚动位置）。

### 2.5 历史按时间段筛选

「按时间 / 按站点」右侧新增「全部 / 今天 / 近 7 天 / 更早」胶囊：

- 今天 = 本地自然日 0 点起；近 7 天 = 最近 7×24 小时；更早 = 7 天以前；
- 过滤顺序：时间段 → 搜索词 → 视图；「按站点」的聚合次数与最近访问时间都按过滤后集合重算；
- 记忆在 `localStorage['nyx:tb:history-range']`（非法值退回全部）；meta 带后缀，如「共 4 条 · 2 个站点 · 命中 2 条（今天）」。

## 五、已知边界

1. 安装版仍为 1.2.9，本次只构建发布，未强装。
2. **差分对真实安装包基本无效**（实测 0%），闸门会在 20% 以下直接整包；真正省流量的路子在「未压缩资源差分」或「增量分发」上，属于分发形态改造，暂不做。
3. 更新源目录里累积了 1.2.9 以来的多个安装包（约 850MB），升级时 installer 会删 `*.exe`；如需立刻腾空间可手工清理旧包（留档目录不受影响）。
4. 「已打开」提示基于 URL 精确匹配：带不同 query 的同一页面仍算不同 URL。
5. 抓包列表图标只为可见行请求，快速滚动时补图约有 1 帧延迟。
