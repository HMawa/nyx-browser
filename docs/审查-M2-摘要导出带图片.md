# 审查单：摘要导出连图片（M2）

> 交付口径：现象 → 取证（文件与行号）→ 改了什么 → 验证数字 → 能证明什么 / 不能证明什么 → 复验命令。
> 日期：2026-11-23｜提交：`feat(digest): 摘要导出可以连图片一起存（默认关闭，隐私模式拒绝）`

---

## 1. 现象

用户的原话是「抓取要做到，页面上所有的图面或标志全能保存到本地」，我拆成三件：

1. 工具箱「资源」页能扫出本页所有图片并勾选保存（**M1，已交付**）；
2. **页面摘要导出时，也把图片一起存下来**（本项 M2）；
3. 整页长截图（M3，未开工）。

第 2 件当时的处境：摘要导出只有「导出 .md」「导出 CSV」两个按钮，导出的 Markdown 里只有小标题、摘要句子、关键词与网络统计，**一张图都没有**。离线缓存 v2 也是刻意只留 alt 文本，`src/renderer/renderer.js:539` 的注释写着「图片只显示 alt：我们不把图片二进制抓到本地磁盘」。

也就是说：把摘要存成文件之后，读者拿到的是「一段没有图的文字」，而页面上那些图（往往就是理解内容的关键）并没有跟着走。

## 2. 取证

| 位置 | 事实 |
| --- | --- |
| `src/core/page-digest.js:40` | `buildExtractScript()` 只取 headings / text / lines，**完全不采图片** |
| `src/core/page-digest.js:385` | `buildDigestMarkdown(payload, options)` 只拼标题、来源、时间、小标题、句子、关键词、网络统计 |
| `src/main.js:12131` | `ipcMain.handle('nyx:digest:export')` 先 `showSaveDialogSync` 选路径，再 `fs.writeFileSync(target, body)` |
| `src/preload.js:251` | `digestExport: (result, format)` 只透传两件事，没有位置放开关 |
| `src/renderer/index.html:517` | 侧栏只有 `#digest-export`（.md）与 `#digest-export-csv` |
| `src/core/media-collector.js`（M1 新增） | 已有 `buildCollectorScript()` + `normalizeCandidates()`，能扫出 img / CSS 背景 / 内联 SVG / favicon / video 封面六类 |

结论：**不必重写摘要抽取**。图片本来就能扫（M1 已经做完），缺的是「导出时把扫到的图落到磁盘，并在 Markdown 里引用它们」。

## 3. 改了什么

### 3.1 新增 `src/core/digest-assets.js`（纯逻辑，零依赖）

| 函数 | 做什么 |
| --- | --- |
| `pickAssets(items, {maxCount})` | 从 M1 的候选里挑图片：只认 `image / background / svg / poster / icon`；按 url 去重；`blob:` 与其它非图片**逐条记原因**；超出上限（`MAX_ASSETS = 40`）的也记原因 |
| `assetFileName(item, index)` | `03-站点图标.png`：序号在前（与 Markdown 顺序一致）；文件名走 M1 的 `sanitizeFileStem`（Windows 保留字符、保留名、超长都处理）；扩展名认不出时按种类兜底 |
| `assetDirName(mdPath)` | 由 md 文件名推出图片目录名（`页面摘要-…_assets`） |
| `appendImageSection(markdown, saved, skipped, {dirName})` | 在**署名之前**插入「## 本页图片」：相对路径引用 + 尺寸；跳过原因按相同理由归并成「> - 原因（N 张）」 |
| `describeAssetExport({saved, skipped})` | 状态栏一句话，且「一张都没存下」不会被说成成功 |

`MAX_ASSET_BYTES = 2 * 1024 * 1024` 与预览同口径：导出是留档，不是搬运原图。

### 3.2 `src/main.js`

- 新增 `fetchImageToFile(url, filePath)`：`data:image/svg+xml` 本地解码直接写（**不发请求**）；http(s) 走 `electronNet.fetch`（跟随已配置代理）+ 8 秒 `AbortController` + 只收 `content-type: image/*` + 单张上限。
- 新增 `exportDigestAssets(markdownPath)`：**先判隐私模式**（隐私模式下不发任何请求，只把「没取图」的原因写进 Markdown，因为 `electronNet.fetch` 走默认 session、不在隐私分区那条代理之下）；再扫当前页 → `pickAssets` → `fs.mkdirSync(dirPath, {recursive:true})` → **逐张 await**（串行，不把对端站点打成并发）→ 成功/失败分别收集。
- `nyx:digest:export` 增加 `includeImages`：只在 Markdown 下生效；先算图片小节再一次性写 md；返回里带 `images: {saved, skipped, dir}` 或 `imageError` 与 `summary`。

### 3.3 界面

- `src/renderer/index.html:518`：新增 `#digest-export-images`「导出 .md（含图片）」，提示里写明「隐私模式下不取图」。
- `src/renderer/renderer.js`：`exportDigest(format, options)` 认 `includeImages`（按钮各自禁用，避免重复点）；成功时把 `res.summary`（已存/跳过）接到状态栏。
- `src/preload.js`：`digestExport(result, format, options)` 透传 `includeImages`。

## 4. 验证

| 项目 | 结果 |
| --- | --- |
| `node scripts/verify-page-digest.js` | **34 / 34 通过**（原有 27 项 + 本项 7 项） |
| 全量 `npm run verify` | **54 个脚本 / 54 通过 / 0 失败 / 0 跳过 / 1244 项** |
| `scripts/verify-all.js` | 第 14 步 items `26 项` → **`34 项`**，标签和 1236 → **1244** |

新增的 7 项断言（都在 `scripts/verify-page-digest.js`）：

1. 只挑图片：视频与 `blob:` 逐条点名跳过，重复 url 不重复存；
2. 一次最多 40 张，超出的每条原因写「超过上限」；
3. 文件名：序号在前、Windows 保留字符被清、扩展名跟地址一致、认不出按种类兜底、`data:` 也有兜底名；
4. 图片目录名跟着 md 文件名走（Windows 与 POSIX 两种路径都测）；
5. Markdown 里「## 本页图片」出现在**署名之前**，相对路径正确，尺寸写出来，跳过原因按条数归并；
6. 一张都没存、全部跳过时**不造空图片语法**，只写原因；既没存也没跳过时原样返回；
7. 主进程契约：隐私判断在扫描**之前**、先 `mkdirSync` 再逐张 `await` 取图、取图走 `electronNet.fetch`、单张上限、`content-type` 校验、内联 svg 在联网分支之前处理；preload 透传、侧栏按钮与文案、renderer 传 `includeImages`。

本轮被断言抓出的两处自身缺陷（都已修）：

- `assetFileName` 拼出过 `01-nyx-media..jpg`（`extFromUrl` 带前导点，我又补了一个）→ 统一剥点；
- 断言里用 `fetchBody.includes('data:image')` 之外的正则判「不发请求」时被源码里的转义绕开 → 改成按**位置**判（内联分支必须在 `^https?` 之前）。

## 5. 能证明什么 / 不能证明什么

**能证明**：勾了「含图片」之后，Markdown 里会多出「## 本页图片」小节、图片落在同目录 `_assets/`、取不到的逐条写原因；隐私模式下**一次请求都不发**，并把这件事写进文件；上限与类型检查都在。

**不能证明**（如实写在这里，别在交付里含糊）：

1. **跨域样式表里的背景图扫不到**——扫的是计算后样式，跨域 CSS 的 `background-image` 按同源策略拿不到；这与 M1 的边界同一条。
2. **`blob:` 图只能趁页面还开着**——它在导出那一刻已经失效时，只会记一条跳过原因。
3. **没有做"整页长截图"**——那是 M3。
4. **图片只存一遍，不重编码**：站点给的什么格式就存什么格式（`avif` / `webp` 原样），不转码。
5. **图片目录与 md 是并列关系**：单独把 md 发给别人，图片会丢——文件里用的是相对路径，这一点写在 README 级的文档里。
6. 本次用断言 + 纯逻辑覆盖，**没有在真机界面上点一次「导出 .md（含图片）」并肉眼验收**（保存对话框是模态的，自动化点不了）；这条属于人眼项。
