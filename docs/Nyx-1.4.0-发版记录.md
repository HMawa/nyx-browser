## 二、逐项说明

### 2.1 建议按访问频次加权

原来只有"前缀命中 + 最近访问"两个维度，结果是**新打开一次的页面永远压过天天用的老页面**。现在改成打分制（`SUGGEST_WEIGHT`，集中在一处，便于后续调参）：

| 维度 | 权重 | 说明 |
|---|---|---|
| 前缀命中（网址/主机名以输入开头） | +100 | 最直观的意图信号 |
| 已收藏 | +60 | 用户主动表达过的偏好 |
| 历史访问次数 | 每次 +5，上限 10 次封顶（+50） | 防止常驻站点永远霸榜 |
| 最近访问 | 30 分起，每远离一天 -3（30 天归零） | 新鲜度衰减 |

同分时按最近访问时间倒序、再按 URL 稳定排序（避免每次查询顺序抖动）。

访问次数怎么来：历史存储的"5 分钟去重窗口"之外，同一 URL 会有多条记录，**条数即近似访问次数**；主进程查询时聚合一次，不新增数据结构、不改历史文件格式。

### 2.2 「搜索「输入」」直通行

- 复用主进程既有的地址栏规范化规则（`normalizeInput`）：只有规范化结果落在搜索分支时，才在建议末尾补一条 `搜索「输入」`；输入域名 / IP / 带协议地址时不会多出一条"搜索"，行为与直接回车完全一致。
- 已经满 8 条时**挤掉最后一条历史建议**，保证搜索行永远可见（用户可能就是想搜）。
- 浮层里这一行用描边徽标「搜索」+ 「回车直接搜索」副文案，和实底「书签」徽标区分。

### 2.3 工具栏书签星标

- 地址栏右侧新增 `☆/★` 按钮：点一下收藏当前页，再点取消；状态由主进程（书签存储）是唯一真相，渲染层只做展示。
- 新增两个 IPC：`nyx:bookmarks:has`（查询是否已收藏）与 `nyx:bookmarks:toggle`（收藏/取消，返回最新状态）；切换后推 `nyx:bm:changed`，书签栏 / 工具箱 / 星标一起刷新。
- 只有 `http(s)` 页面可收藏（`about:blank`、内部页、本地文件自动禁用并置灰）。
- 状态按"当前地址"缓存，避免每次标签状态推送都问一次主进程；标题与提示文案随状态变化（收藏当前页 / 已收藏（点击取消收藏））。

### 2.4 星标与建议联动

- 收藏后星标立即变 `★`；如果地址栏建议正开着，会**立刻重查一次**，让刚收藏的地址带上「书签」徽标、并按书签权重前移。
- 反之亦然：在工具箱 / 书签浮层里增删书签，星标收到 `nyx:bm:changed` 后同步刷新。

### 2.5 打包体积优化

| 指标 | 改前（1.3.1） | 改后（1.4.0） |
|---|---|---|
| locales | 55 个 / 46.6MB | **2 个 / 1.1MB**（en-US + zh-CN） |
| win-unpacked | 439.4MB | **393.9MB** |
| 安装包 | 121.2MB（127,039,037） | **113.2MB（118,686,184）** |

- 配置：`build.compression: "maximum"` + `build.electronLanguages: ["zh-CN","en-US"]`。
- 净减约 8MB（-6.6%）。语言包在 LZMA 下本就压到极小，砍掉 45.5MB 原始体积只换来约 8MB 安装包体积；剩余大头是 `Nyx.exe` 227.8MB / `mihomo.exe` 58.2MB / `dxcompiler.dll` 24.4MB / `geoip.metadb` 8.1MB，**不改二进制到不了 100MB 以内**。
- 明确不做的三项（已评估）：`LICENSES.chromium.html` 删除违反再分发许可义务；`dxcompiler` / `vk_swiftshader` 属图形栈回退，删了可能黑屏或 WebGPU 异常；mihomo UPX 净省有限且易触发杀软误报、影响内核稳定性。

## 五、已知边界

1. 安装版仍为 1.2.9，本次只构建发布，未强装。
2. 访问次数用"历史记录条数"近似：历史上限 5000 条，超出后最旧记录被裁剪，极长期高频站点的计数会随时间衰减（属预期）。
3. 建议上限 8 条（含搜索行），搜索行占最后一位；若用户希望搜索行置顶，改 `addressSuggestMatches` 末尾的插入位置即可。
4. 星标只支持 `http(s)` 页面；内部页（`nyx:`）、本地文件、`about:blank` 禁用。
5. 打包体积已到"不改二进制就下不去"的平台期：继续压缩需要动 mihomo / Chromium 组件，风险收益比不划算，暂不做。
